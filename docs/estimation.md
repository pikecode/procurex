#### 3.2.12 v1.3 范围变动与重估清单

| 工作项 | 已确认范围 / 重估重点 |
|---|---|
| 三种周期单据 | 门店+供应商+周期销售价账单；供应商+周期及供应商+周期+门店供货价汇总单，共用应付和核销明细、防重复计账 |
| 发货日期归账 | 按原执行订单首次发货日期归自然周、半月、自然月周期；跨期补发仍归原周期、沿用原单价格，不新增订单 |
| 已出账调整 | 未结清账单更新并留痕；已结清保留原值，生成关联差额调整单参与后续结算，供应商总单/分店单共用调整明细 |
| 资金不足流程 | 余额不足可提交，采购提示缺口但不能确认/拆推；充值后采购重新校验，扣款、退款、释放额度及并发幂等 |
| 供应商分配 | 按分类批选，每条商品一家；拒单回采购重新分配或取消，金额随分配调整 |
| 价格版本 | 采购双端改价，已发货未完成订单按生效时间与发货时间比较重算，保留差额记录 |
| 双端供应商流程 | 网页和小程序均支持发货、物流单号、补发、退回确认、同意及收款确认；商品/供应商资料不可编辑 |
| 财务操作与权限 | 充值、挂账额度和清账归总部财务/管理员，图片凭证与操作人日期可追溯；成本利润字段隔离 |
| 结算方式 | 四种方式，储值/挂账仍生成公司供应商应付；已确认供应商默认、门店模板可覆盖，覆盖值优先 |
| 首版排除 | 不含入库、出库、库存、第三方门店同步、在线支付、审批流；保留单组单位换算 |
| 重复工项 | §3.2.6 门店字段与 §3.2.7 门店维护需合并去重后估算，不能简单累计 |

本表变更还需同步设计、接口、数据权限和端到端测试工时。历史合计不自动覆盖新工作量，不能在未重估时继续承诺 19 周完成。

## 7. 优化建议

以下仅保留旧版压缩方案供参考，不能据此删除已经确认的历史改价、利润报表等首版需求，调整范围须另行确认：

| 压缩项 | 可省 | 代价 |
|---|---|---|
| 报表导出功能延后 | -1.0 | 首版无导出，运营手动查 DB |
| 小程序组件库用现成 UI（如 TDesign） | -1.5 | 视觉一致性弱化 |
| 性能压测改上线后补 | -0.5 | 上线初期需关注 |
| 门店维护首版仅保留必要字段 | -0.5 | 暂不做复杂门店资料扩展字段 |
| 价格生效时间首版不支持过去时间 | -1.0 | 无法满足未完成订单按历史生效价重算 |
| 利润报表延后 | -1.5 | 首版仅保留供应商应付和门店应收明细 |

旧表差值合计 6.0 人天，不适用于 v1.3 的交付承诺；本轮不据此提供 89 人天排期。
