# 小程序角色交互优化：总结文档

## 2026-10-17 统一异常处理与双方结单（最新）

本节覆盖此前“数量差异可直接按实收完成”“数量异常还需再次提出整单异议”的交互约定。

- 门店异常收货一次提交即进入供应商待办，数量与质量异常一致。少收录入是事实记录，不允许门店自行改变结算数量；异常提交后本批发货及收货数量锁定。
- 供应商数量异常入口为“安排补发 / 不再补发”，回复说明必填、图片选填，并显示原发货/实收/少收数量。补发方案执行中可“调整为不再补发”，只撤销尚未发出的补发计划；门店不接受时可继续异议，保留全部回复历史。
- 门店未收到补发前不显示“确认已解决”；供应商不再补发时显示“接受不补发，按实收结算”，确认后仅解决异常，最后再“确认整单完成”。供应商原始未足量发货的整单拒补方案，门店可以“接受不补发并完成”或继续提出异议。
- 任何未解决异常、未登记的发货批次或没有双方确认依据的最终少收，都禁止完成接口，不能只隐藏按钮。新数量异常直接走收货记录回复与现有差异补发缺口；不新增重复工单，不将正常分批未发商品混入补发。
- 本地增量迁移把尚未进入既有异议/补发流程的未完成OPEN数量差异纳入统一待办，不改已完成订单、数量和金额；本轮未部署服务器。
- 供应商详情头部和履约提示复用列表状态口径，待供应商处理时不会错误显示“发货结束待门店确认”。本地API已重启并保持本地地址；自动化验证包括261项单元测试、245项小程序测试、18项履约数据库集成测试、界面/契约/结构检查及原生模板编译。本次未重跑此前尚有旧断言待对齐的全量集成套件，不宣称全量系统验收通过。

## 2026-10-17 异常回复凭证

供应商“回复已处理/无法处理”展开本批回复表单：处理说明必填，处理凭证选填（最多6张），可添加、移除、取消或提交；上传和提交期间锁定导航，失败保留草稿。供应商与门店异常区域按时间展示每次回复及其缩略图，支持原有凭证预览。再次提出异议不覆盖之前的回复与图片。

## 2026-10-17 订单详情信息分层

顶部集中显示订单主体、状态、单号、商品/批次数与金额，内容区改为“商品 / 发货 / 异常”三个视图。有未解决或历史已登记异常时优先展示异常；无异常但有待收批次时展示发货，其余展示商品。异常按批次分隔，备注、凭证、回复集中在同一记录，凭证使用紧凑缩略图；发货列表仅保留批次状态、单号、物流和收货/异常入口，不重复展开异常内容。供应商联系、创建时间、来源下货单放入可展开的订单信息区。整单收货确认独立保留，权限和处理状态不变。

## 2026-10-17 收货提交后的订单跟进

订单详情的异常展示统一覆盖数量差异和非数量异常，不再仅以 `receiptExceptionStatus` 非空判断。异常区域显示批次号、备注、凭证，少收时显示本批发货/实收/差额；各发货批次同步显示异常状态及“查看异常详情”，整单未解决提示可直接定位异常区域。普通收货备注不自动视为异常，数量异常无独立处理状态时显示“数量差异已登记”，不能误标为已解决。

收货提交成功（含原请求重试核对成功）统一自动进入该发货批次所属供应商订单详情；不再停留混有待收货列表的结果页。订单顶部显示本批登记成功反馈。未提交前取消，仍按原进入位置返回。

数量一致的收货异常提交即通知供应商并进入待处理，订单中展示备注、凭证与状态，不再要求二次提交。供应商在待办/异常订单填写处理回复，回复已处理或无法处理后，均由门店决定确认解决或重新提交。异常未解决不可完成订单；数量差异继续走原有实收确认与补发异议流程。

## 2026-10-17 门店订单与收货导航统一

| 进入位置 | 核对本批收货后的返回位置 |
|---|---|
| 订单详情的发货批次 | 原供应商订单详情，保留订单列表的筛选 |
| 下货记录详情的发货批次 | 原下货单详情 |
| 收货待处理中的批次 | 待收货批次列表；列表再返回订单列表 |

- 待收货批次来自 `/shipments/pending-receipts` 的真实批次及当前收货记录，包含未登记批次和退回重核批次，按发货时间从早到晚排序。已登记差异、已结束的批次不会因旧通知重复出现；无通知也能显示，取消原先20条通知截断。
- 正式订单标签与筛选共用状态判断：待收货（有待核对批次）、待确认（发货结束且批次已登记）、异常处理（异议、拒绝补发、待补发或历史差异）、待发货、发货中、已完成、关闭/拒单。待收货优先于补发状态，补发已有新批次到货时可直接找到收货入口。标签数量随搜索和日期条件同步，在分页前统计。
- 数量单位明确区分：订单筛选以“张”为单位，收货待处理以“批”为单位。移除底部订单旁原先显示批次数的角标，避免与待收货订单张数混淆。
- 列表按待收货、待确认、异常处理、待发货、发货中、已完成、关闭排序；未完成分类按订单创建时间从早到晚，完成/关闭从晚到早，同时间以ID稳定排序。详情不再显示上层“订单/下货记录”切换，子页面标题与返回目标匹配。
- 核对页明确提供正常收货/异常收货。选择异常后填写实际收到的数量，上传凭证，再登记异常；数量减少也自动切到异常。供应商结束发货、全部批次登记后，在订单中选择按实收结单或提交供应商处理，登记单批不等于完成整单。
- 历史收货差异仍可从收货待处理或对应订单进入处理，过滤为该订单，保留历史按实收结算/要求补发规则。
- 验证结果：222项小程序逻辑测试、255项服务端单元测试、7项真实数据库履约测试通过，接口契约与原生模板编译通过。模拟器使用门店9现有数据核对2张待收货订单/4个待核对批次，验证订单来源返回、批次列表来源返回及正常/异常收货显示；未提交或修改用户的实际订单。新增待收接口已在本地及服务器版本 `20261017-batch-receipt-workflow` 启用，小程序微信版本尚未上传发布。

- 2026-10-17 补齐为九个筛选：全部、待发货、发货中、待收货、待门店确认、异常处理、待补发、已完成、已关闭。已拒单和已取消合并在已关闭内，列表标签保留关闭原因。

- `IN_PROGRESS` 归发货中；`FINISHED` / `DECLINED` 有待核对批次归待收货，批次均已收货后归待门店确认。供应商已回复的收货异常等待门店确认，不再混入待收货。尚待供应商回复的收货异常优先归异常处理；整单 `DISPUTED` 也归异常处理。`REPLENISHING` 归待补发，`COMPLETED` 归已完成，完成/关闭状态优先于过期异常计数。待发货仅包含尚未开始发货的已推送/已接单订单。

## 一、先纠正一条错误结论

此前的评审结论称「底部同时存在原生 tabBar 与自定义导航两层，二者重复」。该结论有误：项目已设 `tabBar.custom: true`，角色切换由 `custom-tab-bar/` 承担，且仅在 `workspaceNames` 返回多于一项、用户非 ADMIN、未启用测试工作台时才显示。单角色用户与管理员只看到页面内的任务导航。用本地七个账号逐一复核，底部为一层导航，无需改动。本文按纠正后的实际结构推进。

## 二、O1 空状态补充引导动作

供应商待办页原先三个分组为空时只渲染一行文字（「暂无待发货订单」「暂无待处理异常」「暂无收货异常记录」），三个计数同时为 0 时整页下部大片留白，用户既不知该做什么，也易误判系统异常。

现于前两处空状态内各补一个次级按钮，分别指向仍有内容的去向：待发货为空时「查看已发货订单 ›」切至订单页并预置 `SHIPPED` 筛选；少收核对为空时「查看收货异常记录 ›」切至异常页。第三处为常驻入口行，改为在计数为空时追加一行提示文案指向对账页，不加按钮以免与该入口行的点击行为重复。

新增 `gotoView` 方法统一处理"切视图 + 预置筛选 + 刷新列表"，复用既有的 `changeView` 与 `filterStatus`，未新增跳转机制。

采购与公司财务页未改动：经检查其空状态所在位置已有明确的同页去向，追加按钮属凑数。

## 三、O2 起订量与倍数提升为约束级样式

门店商品列表原先将「起订 4 · 倍数 2」与销售单位并置于 `.product-meta`（21rpx、灰 `#718078`），是全页最小的正文字号。而这两项是提交硬约束，低于起订量或不符合倍数即被拦下，其视觉权重却低于商品名（28rpx）与价格（30rpx），用户往往到提交时才察觉。

现从描述行移出，改置于价格旁的 `.product-price-group` 内，字号提至 24rpx，颜色改为提示色 `#8b601e`，与价格处于同一视线。仅在 `canOrder` 为真时显示，对不可订商品不增噪音。

## 四、O3 部分完成：保留角标，撤回汇总条

原计划在商品列表上方加一条常驻汇总（「已选 N 种 · 预估 ¥X」），滚动时不必回到底部查看。实施后测试失败：

```
assert.ok(!template.includes('预估 ¥'))
```

该断言出自今日提交的 `8d191fc`，与另一条"`estimatedAmount` 在模板中恰好出现 2 次"的计数断言配套，表达的是一项**既定设计决策**：预估金额只出现在底部固定栏与购物车弹层，商品目录区不重复呈现，避免同一数字在三处并存造成视觉冗余。

该决策合理——汇总条与底部 `.order-bar` 内容完全相同，功能上无增益。故撤回汇总条及其样式，**保留每行的已选数量角标**：角标回答的是"这一行加了多少"，与底部的"总共加了多少"不重复，且不违反任何既有断言，符合原设计意图的前提。
