# 门店页视觉交互优化：总结文档

完成日期：2026-10-11。对应落地文档 `store-page-ux-plan.md`。

## 一、保留未动的部分

左右分栏骨架与独立滚动区（`.catalog-browser` 配 `.catalog-products { flex: 1; height: 0 }`）经核对是正确的纵向滚动写法——底部操作栏不参与商品列表滚动，本轮未改动骨架、接口、权限与结算规则。

## 二、逐项完成情况

### O1 分类侧栏两行截断

侧栏宽 154rpx、字号 24rpx，原先仅有 `overflow-wrap: anywhere`。实测最长分类名 22 字符，业务常见的「冷冻冷藏食品」也达 6 字，超出后折行并呈单字竖排，侧栏失去扫读能力。

改为 `-webkit-line-clamp: 2` 两行截断，并收紧内边距。选中态仍由左侧色条与字色标识，不依赖文字完整，长名称下依然可辨识。

### O2 商品行收敛

按实测填充率：储存条件 49/58（84%）、规格 31/58（53%）、品牌 0/58，原先最多渲染 6 至 7 行。

- 规格、品牌、储存条件合并为**一行**辅助文本，多余以省略号收尾，无内容时不渲染该行
- 销售单位不再单独成行，并入价格行的 `/ 单位` 位置
- 采购单位换算**仅在商品已加入清单后展开**；未加入时以「可按{{采购单位}}下单」一行提示，避免漏看也不占高度

常规商品行收敛为三行：商品名 / 价格与起订倍数 / 数量步进器。

### O3 价格与步进器同行

`.catalog-content .product-bottom` 此前为纵向排列，价格左对齐、步进器 `align-self: flex-end` 右对齐，分处两行后失去关联。恢复横向排列，步进器设 `flex-shrink: 0` 且 `margin-left: auto` 靠右，价格区设 `flex: 1; min-width: 0` 允许内部换行而不挤压加减号。

### O4 搜索结果标注覆盖分类

原判断有误：`onSearch` 已将 `primaryCategoryId` 清空，侧栏高亮本就回落到「全部」，不存在高亮不同步。

真实缺口是管理员无法得知结果覆盖哪些分类。改为在搜索时计算结果涉及的分类名，在列表上方显示「匹配分类：××」。仅改展示，不动筛选逻辑。

### O5 数量角标避让占位文字

角标固定于商品图右上角，无图时该区域显示「暂无图片」等文字且垂直居中，二者可能重叠。占位区改为底部对齐并收紧字号，让出右上角。

### O6 空状态提供解除动作

「没有匹配的商品」新增「清除筛选」按钮，一键清空搜索词与分类选择；新增 `clearCatalogFilter` 方法复用既有的 `refreshCatalogView`，不引入新的筛选状态。

## 三、顺带修正

`store/index.wxss` 补齐 `.empty-action` 与 `.search-scope-hint`。`.empty-action` 此前只在 `styles/workspace.wxss` 定义，而门店页使用自有 wxss，不在其作用域内。

## 六、遗留

- 数量输入框 80rpx，大数量数值需横向滚动
- 收货凭证区位于 `selectedShipment` 判断之外，物理位置在 block 外，后续改动易误触
- `.catalog-page` 与 `.store-page` 两套底部留白并存，是此前遮挡问题的来源
- 字号收敛仍只在 `app.wxss` 留有刻度约定，未实际调整
