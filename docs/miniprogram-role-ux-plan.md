# 小程序角色交互优化：落地文档

制定日期：2026-10-11。范围限于 `apps/miniprogram` 的视觉与交互，不改后端接口与业务规则。

## 一、已确认不再处理的事项

**底部双层导航不存在。** 此前判断有误：`app.json` 已设 `tabBar.custom: true`，底部角色切换栏由 `custom-tab-bar/` 承担，且仅在 `workspaceNames` 返回多于一项、且用户非 ADMIN、未启用测试工作台时才显示。单角色用户与管理员只看到页面内的任务导航。经用本地七个账号复核，确认为一层导航，无需改动。

## 二、业务背景

小程序承载采购协同的五个角色，每个角色的首页承担不同职责：

- **门店**：订货、查订单进度、按批次收货、查看账户与账单
- **供应商**：处理待发货订单、少收核对与补发、维护对账
- **采购**：审核门店订货、分配供应商、处理异常与费用
- **门店财务 / 公司财务**：查看资金账户、流水与结算账单

各角色首页的共同结构是「若干任务分组的列表」，因此任务为空时的呈现方式直接决定用户对页面是否"有事可做"的判断。

## 三、缺陷

### D1 空状态为纯文字，无下一步动作

供应商待办页的三个分组各自渲染 `暂无待发货订单` / `暂无待处理异常` / `暂无收货异常记录` 一行文字，无按钮。当三个计数同时为 0 时，整页只剩标题与空状态文字，下方约四成屏幕留白，用户既不知道该做什么，也容易误判系统异常。

采购与公司财务页存在同类问题，程度较轻。

### D2 下单硬约束的视觉权重过低

门店商品列表中，起订量与订货倍数与商品单位并置于 `.product-meta`：

```
茉莉茶叶｜常规订货 · 起订 4 · 倍数 2
```

该样式字号 21rpx（约 10.5px）、颜色 `#718078`，是全页最小的正文字号。而这两项是下单硬约束——低于起订量或不符合倍数倍数无法提交——却比商品名（28rpx）和价格（30rpx）弱得多，用户容易忽略并在提交时才被校验拦下。

### D3 购物车状态仅存在于底部悬浮栏

商品目录页的已选数量与预估金额只出现在 `.order-bar`（`position: fixed`，位于底部导航之上）。商品列表较长时，用户滚动至列表中部或末尾，该信息不在视口内，无法随时确认已选种数与金额。

## 四、方案

### O1 空状态补充引导动作（对应 D1）

供应商待办页的三处空状态各补一个次级按钮，指向该分组之外仍有内容的去向，避免用户在空页面里无处可去：

- 待发货为空 → 「查看已发货订单」，切至订单页并预置发货状态筛选
- 少收核对为空 → 「查看收货异常记录」，切至异常记录页
- 收货异常记录为空 → 「查看对账」，切至对账页

采购与公司财务页的空状态按同样原则处理，但仅在存在明确去向时补按钮，不为凑数而加。

验收：三个分组全空时，页面不再出现无指引的留白；点击按钮可到达对应页面且筛选已预置。

### O2 起订量与倍数提升为约束级样式（对应 D2）

从 `.product-meta` 中移出，改为独立的价格区元素：字号提至 24rpx，颜色使用提示色而非正文灰，与价格同处商品底部一行右侧，使"能订多少"与"多少钱"在同一视线内。

同时补充下限提示，仅当商品存在起订量约束时显示，避免对无约束商品增加噪音。

验收：起订量/倍数的字号与颜色明显区别于商品描述；在 390px 窄屏下不换行、不挤压价格。

### O3 购物车信息在商品列表内可见（对应 D3）

为已加入清单的商品行加一个已选数量角标，配合列表顶部一条轻量的汇总条（在搜索与分类之下、商品列表之上），显示已选种数与预估金额。底部 `.order-bar` 保留，承担下单动作。

这样用户在列表任意位置滚动时，既能看到每行加了多少，也能看到总额，不必回到底部。

验收：滚动到列表中部时，已选信息仍在视口内；底部操作栏功能不变。

## 五、不做的事

- 不改后端接口、权限与结算规则。
- 不改 `custom-tab-bar` 与页面内导航的任何结构。
- 不新增库存或进货单页面（用户已确认暂不开）。
- 不做字号全局收敛，仅在本轮改动处使用既有刻度。

## 六、风险

- O1 的按钮需要各角色页面已有的 `changeView` 或筛选 setter，若某页缺少对应入口则只保留文字提示，不强行跳转。
- O2 会使商品行底部一行变宽，需复核 390px 窄屏与 `@media (max-width: 350px)` 断点下的换行表现。
- O3 的顶部汇总条与底部 `.order-bar` 存在信息重复，需保证两处数值口径一致，均以 `cartCount` 与 `estimatedAmount` 为准，不另算。

## 七、验证方式

本轮仍不做真机自动化验证。`npm run mini:check` 与 `npm run mini:test` 通过后交由用户在微信开发者工具中逐角色走查。
