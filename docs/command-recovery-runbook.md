# 提交恢复与遗留调用操作手册

日期：2026-10-05。对应C7/L6，仅使用已交付接口；不新增全局解锁、自动补偿或历史回填。

## 写入口键合同

以下合同以当前控制器及68个业务写/预览入口清单为准，不沿用“所有POST都有键”的旧概括。

| 分类 | 接口/动作 | 键与失败边界 |
|---|---|---|
| 必须有键：采购 | 创建请求、拒单改派、确认、拒绝 | 原账号+动作+原键+原请求；含资源ID，不能改版本或内容冒充重试 |
| 必须有键：履约 | 发货、运费申请/确认/拒绝、供应商拒单/资金重核、门店收货、差异处理 | 成功结果与业务/资金/审计同事务；成功重放不再执行，当前范围仍必须获准 |
| 必须有键：账户 | 充值、额度修改、清账 | 正式Web要求充值/清账图片；旧API可省略图片，不伪造旧凭证 |
| 必须有键：付款/差额 | 付款创建/确认/拒绝/撤销，差额创建/确认 | 明确失败重放原错误；未知结果保留PROCESSING，禁止按过期换键再执行 |
| 必须有键：管理员处置 | commands/:id/reviews、close-rolled-back-price、close-uncommitted-price | 人工审阅不改变原命令；关闭仅限服务端能够证明结果的价格任务 |
| 可选键的四个旧动作 | POST price-changes；POST jobs/:id/process；PATCH purchase-requests/:id/items；POST purchase-requests/:id/assign | 带键走原子命令；省略键仍业务/审计同事务，标记LEGACY_HEADERLESS，无CommandRecord，无原键精确恢复 |
| 无命令键：主数据 | 分类/单位/品牌/商品/供货/模板/门店/用户等27个写入口 | 认证操作者、版本/原锁及业务审计同事务。创建看业务唯一标识，修改看当前版本；响应丢失先读，不重复创建/复制 |
| 无业务执行：预览 | 报价、价格影响、采购创建/明细/改派预览、发货/付款/清账预览 | POST也可能只读；不得把预览成功当作业务已提交 |
| 无资金命令：文件/导出 | 上传会话、内容上传、完成；报表导出/重试 | 保存原文件/作业ID，按原用途、归属、状态操作；不新建付款或重复关联凭证 |
| 会话/个人已读 | 登录/退出、notifications/read-all及:id/read | 自身会话/收件人校验；不要求门店业务范围，不是全局业务写权限豁免 |

## 先保留再核对

1. 保留原服务地址、账号、动作、资源/业务编号、请求体、版本、幂等键和traceId；不要把密码、上传令牌或付款图片写进普通交接记录。
2. 原账号GET /commands查看自己的脱敏摘要。ADMIN可GET /commands/stale?limit=100；分页能力未提供，超过100条不能声称全量核对。摘要不包含原键、请求hash或业务响应，不能从摘要重新构造原请求。
3. 按下表读取资源，并由ADMIN/HQ_FINANCE用GET /audit-logs?actorUserId={id}&action={action}&traceId={traceId}&limit=100核对。查不到审计、余额未变或任务看似待处理都不是确定未提交的证明。
4. 账号范围已改变时，业务GET或原键重放可返回403/404。原命令保持不变；由有权管理员核对，不能绕过范围或修改原记录。恢复合法原范围后原成功键仍可返回原结果。

| 原动作 | 只读事实入口 | 核对重点 |
|---|---|---|
| 价格发布/执行 | POST /prices/quote；GET /price-scopes/:id/versions；GET /jobs/:id、/adjustments、/submissions | 来源版本/生效时间、任务状态及调整、订单和资金事实；无键历史不会出现在命令历史 |
| 请求创建/编辑/指派/确认/拒绝 | GET /purchase-requests及/:id，GET /supplier-orders | 原申请号、模板、明细、价格来源、版本、拆单及状态，不能仅凭订单条数猜原结果 |
| 发货/运费/拒单/资金重核 | GET /supplier-orders/:id、/freight-confirmations；获准角色GET /shipments/:id | 运单/批次/数量、运费审批、原订单状态及资金来源；不要补发同一批次 |
| 收货/差异 | GET /shipments/:id、/discrepancies/:id、/adjustments | 当前收货修订、凭证、缺货/补发/退回与原调整，不能再次登记相同收货 |
| 账户动作 | GET /stores/:id/account、/ledgers、/credit-items、/recharges/:documentId、/clearings/:documentId | 原单据/余额/冻结/挂账/清账来源、时间、操作人及附件。当前余额不能证明某次提交结果 |
| 付款/差额 | GET /payment-records/:id、/difference-disposals/:id、四类账单及/adjustments | 方向、状态、分配/核销/抵扣来源、原业务日期及凭证；反方向或他方文件仍拒绝 |

## 状态决策

| 状态/证据 | 允许操作 | 禁止操作 |
|---|---|---|
| SUCCEEDED且当前范围有权 | 原账号、原动作、原键和原参数重放；返回原结果，不新增业务/审计 | 改请求内容后沿用原键；改绑后读旧范围结果 |
| FAILED且有明确业务错误 | 原键得到原失败；阅读事实、修正原因后再显式发起新的业务请求 | 当成未知结果盲目重复；用新键覆盖旧失败记录 |
| PROCESSING、未知、无诊断或过期 | 只读核对；ADMIN可记录审阅并冻结该次提交，保留原状态和全部事实，交接给有权负责人 | 删除命令、改FAILED/SUCCEEDED、换键执行、补偿资金；资源已完成也不能伪造原成功响应 |
| 价格任务有服务端回调回滚证据 | ADMIN按原状态及证据调用close-rolled-back-price，提交独立操作键与reason | 客户端提供“回滚证明”或将此接口用于非价格业务 |
| 新原子价格任务有持久化执行合同 | ADMIN调用close-uncommitted-price；服务端锁定命令行核验未提交。关闭后刷新任务，再由原业务校验决定是否新提交 | 对旧/无绑定/错误资源命令使用；把审阅意见或TTL当作执行合同 |
| 旧无键响应丢失 | 按业务标识/版本/任务及审计核对；无法确定时暂停这次业务写入并交接 | 为历史调用生成假键；无CommandRecord就认定未执行；自动复制/重做 |

审阅示例（不是解除命令）：ADMIN POST /commands/{id}/reviews，独立Idempotency-Key，body为{"expectedStatus":"PROCESSING","reason":"核对了哪些单据、尚缺何种结果证据、交接负责人；保持冻结，不重跑"}。返回REVIEW_RECORDED_NO_STATE_CHANGE；原键重复审阅只产生一条审计。没有可靠结果证明时，安全终点是保留未知并冻结，不是宣称已恢复执行。

价格关闭成功后，原业务键返回COMMAND_ROLLED_BACK或COMMAND_NOT_COMMITTED。页面应先刷新任务/价格/订单，不自动执行；其他未知命令没有通用强制关闭入口。这是明确的支持边界，不是待无限开发的自动恢复功能。

## 验收与交接

- unknown-command-boundaries-http.test.ts：24个非价格执行动作（含价格发布）及3个旧/无绑定/错误资源价格情形。真实Nest/DB/HTTP验证过期摘要脱敏、两种价格关闭409、管理员审阅原键重放仅一条审计、原命令完整不变、原键仍阻止执行。命令为隔离历史夹具，不声称实测OS进程崩溃或银行对账。
- role-privacy-matrix-http.test.ts：10个范围相关动作、14个角色/动作组合；已有成功命令在改绑后拒绝，恢复范围后精确重放，无新业务/审计。缓存及已完成单据是隔离夹具，正常真实页面提交另外复验。
- 四旧动作48原子故障案例和核心业务成功/失败/响应丢失回归复用既有证据，不重复改资金逻辑。正式客户端保存原参数/键，不因未知结果自动清除。
- 转交记录至少包含账号/动作/业务编号/traceId、当前状态、已查单据/审计与时间、缺失证据、禁止动作和负责人；秘密只在原受控系统保留。不能把核验未完成记录签成付款已完成。
