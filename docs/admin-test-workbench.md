# Admin 全流程测试工作台

## 范围与权限

- 仅非生产环境且 `TEST_WORKBENCH_ENABLED=true` 时开放；只有当前有效 ADMIN 会话可使用。
- 通过 `TEST_WORKBENCH_USERNAMES` 指定数据库已有测试账号，选择其真实角色和门店/供应商范围；不创建模拟账号，不修改管理员角色或业务数据。
- 每次业务请求重新校验管理员会话、目标账号状态、角色及范围。当前视角不保留 ADMIN 权限。
- 实际操作者保持管理员，审计记录同时保存测试账号、实际角色和数据范围。退出登录或撤销管理员会话后不可继续使用。
- 在单据提交中、上传中或提交结果待确认时不可切换。切换清空页面实例，按测试身份隔离提交恢复记录。

## 交互

- 管理员登录后在底部提供“测试身份”入口；选择账号，确认后进入对应工作区。
- 业务页面顶部展示当前测试身份并提供“切换”；单角色保留原业务底部导航，不叠加第二层导航。工作台提供“返回管理员”。
- 门店厨政、门店财务、供应商、采购和总部财务均复用现有页面及接口。
- 流程：门店下单 → 采购确认 → 供应商发货 → 门店收货 → 财务查询/结算。

## 验证与启用

- 验证默认关闭、生产拒绝、普通账号拒绝、目标不在白名单拒绝、停用/撤权实时生效及业务范围隔离。
- 验证管理员审计归属、切换及返回、未确认提交阻止切换、原有单角色导航不变。
- 本地启动脚本为测试 API 开启工作台，白名单为本地初始化的五类测试账号。已有 API 必须重启以加载新接口及配置；不向服务器部署该入口。

## 使用步骤

1. 关闭旧 API 启动窗口，重新运行根目录 `start-local.sh`，重新编译小程序并使用 admin 登录。
2. 点击“测试身份”，选择储值门店厨政账号，下单后记下订单号。
3. 切换公司采购确认该订单；切换对应储值供应商完成发货。
4. 切回原门店确认收货，再切换门店财务或公司财务查看订单、余额和账单。
5. 点击顶部“切换”可继续切换或返回管理员。测试产生真实单据，不会自动清空。

当前白名单覆盖同一储值门店与供应商的主流程。普通测试账号仍可以独立登录；配置白名单不替代数据库用户管理。

## 2026-10-11 验证结果

- 构建、224 项后端单元测试、131 项小程序测试与小程序结构检查通过。
- 全量接口回归 736 项通过；新增接口清单引起的 9 项权限矩阵失败已修复并全部重跑通过。测试工作台专项含真实充值凭证绑定、余额和管理员审计检查通过。
- 微信开发者工具验证五种身份切换、真实接口数据加载及返回管理员通过。确认弹框仅由自动化自动点击确认，未模拟业务接口。
- 证据位于本地忽略目录 `var/native-test-workbench/manifest.json` 及截图；不是手机真机验收，也未在此次原生验证中重新创建完整业务单据链。
- 当前旧 3114 API 不会自动加载改动；启动脚本检测接口仍为 404 时会提示关闭旧 API 并重新启动。
