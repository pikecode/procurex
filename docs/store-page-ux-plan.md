# 门店页视觉交互优化：落地文档

制定日期：2026-10-11。范围限于 `apps/miniprogram/pages/store/index.*` 与 `components/`，不改接口、权限与结算规则。

## 一、现状与本轮依据

门店页已改为左右分栏：左侧分类侧栏固定，右侧商品区独立滚动（`.catalog-products` 配 `flex: 1; height: 0`）。这是正确的小程序纵向滚动写法，底部操作栏不参与滚动，本轮不动骨架。

本轮只处理信息密度与状态可见性。取值来自当前本地数据（58 个在售商品、若干分类），不是估计值：

| 数据 | 实测 | 对设计的影响 |
| --- | --- | --- |
| 最长分类名 | 22 字符（业务常见「冷冻冷藏食品」6 字） | 侧栏 154rpx 宽无法容纳，必须截断 |
| 规格填充率 | 31 / 58（53%） | 近半数商品多一行 |
| 储存条件填充率 | 49 / 58（84%） | 几乎必填，是行数膨胀主因 |
| 品牌填充率 | 0 / 58 | 当前无数据，仍保留但不单独占行 |
| 采购单位换算 | 少数商品有 | 保留可选项，但不应默认占位 |

## 二、缺陷

### D1 分类侧栏文字无截断保护

`.category-option` 宽 154rpx（约 77px）、字号 24rpx，仅声明 `overflow-wrap: anywhere`。中文分类名超过 8 字即折行，超过字号高度后视觉上呈竖排单字，侧栏完全失去扫读能力，且多行长分类会互相挤压。

### D2 商品行信息可达 6 至 7 行

单行可能依次渲染：商品名 / 销售单位 / 采购单位换算 / 规格 / 品牌与储存条件 / 价格与起订倍数 / 数量步进器。`.catalog-content .product-bottom` 已改为纵向堆叠，价格与步进器各占一行。按实测填充率，84% 的商品会多出储存条件行，53% 再多出规格行。

结果是一屏可见商品数降至 3 至 4 个，订货选品效率低下。

### D3 价格与数量步进器失去视觉关联

`.product-bottom` 改纵向排列后，价格左对齐、步进器 `align-self: flex-end` 右对齐，二者分处两行，管理员无法像横向布局那样一眼把「这个价」和「这个加减」对应起来。

### D4 搜索结果与分类高亮不同步

搜索后左侧分类仍高亮在「全部」，管理员无法判断当前结果覆盖哪些分类，也不清楚清空搜索后分类状态是否复原。

### D5 无图商品上的数量角标压住占位文字

`.cart-badge` 固定在 `.product-media` 右上角。无图时该区域显示「暂无图片」「加载中」或「加载失败，重试」文字，角标与文字重叠，二者都难以辨认。

### D6 空状态无解除动作

搜索无结果时显示「没有匹配的商品」，是一行死文字；管理员需自行逐个清空分类与搜索词。

## 三、方案

### O1 分类侧栏两行截断（对应 D1）

`.category-option` 改为两行截断：`-webkit-line-clamp: 2` 配 `display: -webkit-box`，并保留左侧选中指示条。选中项在两行不足以容纳时，仍应通过左侧色条与字色确认当前项——指示条不依赖文字完整。

验收：任意长度分类名均不折成单字竖排；选中态在长名称下仍可辨识。

### O2 商品行收敛为三行（对应 D2）

- 品牌、储存条件、规格合并为**一行**可省略的辅助文本，多余内容以省略号收尾；无内容时该行不渲染。
- 销售单位并入价格行的单位位（价格后已有 `/ 单位`，不再单独成行）。
- 采购单位换算**仅在该商品被加入清单后展开**；未加入时不占高度。未选中时通过价格行的单位后缀提示可换算，避免用户漏看。

常规商品行收敛为：商品名 / 价格与起订倍数 / 数量步进器。加减号与价格同行两端，维持横向扫读。

验收：常规商品（无换算、无规格）行高不超过三行；带全部可选字段的商品行高不超过四行。

### O3 价格与步进器同行（对应 D3）

`.product-bottom` 恢复横向排列，价格与起订倍数在左，步进器在右，`justify-content: space-between`。在 450rpx 文字宽度内，步进器约 194rpx，价格区约 256rpx，可容纳「¥48.00 / 袋」与「起订 4 · 倍数 2」。

验收：步进器与价格同处一行；两行宽时不换行，必要时价格区内部换行而步进器保持整行。

### O4 搜索时同步分类高亮（对应 D4）

`visibleProducts` 计算时同步得出覆盖的分类集合；若当前选中分类不在该集合内，高亮回落至「全部」。管理员据此判断搜索结果的范围，清空搜索后状态自然复原。

不改接口，不改筛选逻辑，仅调整高亮判定。

### O5 角标避让占位文字（对应 D5）

无图时占位区改为底部对齐的图标加短文案，角标位置不变但尺寸与留白收敛；或将角标移至商品名右侧。二者取其一，以不遮挡文字为准。

### O6 空状态提供解除动作（对应 D6）

「没有匹配的商品」下补一个次级按钮「清除筛选」，点击后清空搜索词与分类选择并恢复完整列表。空状态有明确出路，不再需要管理员逐个退出。

## 四、不做的事

- 不改左右分栏骨架与独立滚动结构，本轮已验证正确。
- 不改接口、权限与结算规则。
- 不动采购单位换算的业务逻辑，只调整其呈现时机。
- 不做字号全局收敛。

## 五、风险

- O2 合并字段后，原先分别可读的规格与储存将共享一行，若二者均较长则其中之一被截断。经确认当前品牌无数据、储存为单值（常温/冷藏等短词），规格多为短值，合并后单行足够；若后续出现长规格，应改为两行而非退回多行布局。
- O3 恢复横排后，若价格区文本过长会挤压步进器。步进器设 `flex-shrink: 0`，价格区设 `min-width: 0` 允许内部换行。
- O4 改动高亮判定后需确认不与既有分类切换逻辑冲突。

## 六、验证

`npm run mini:check` 与 `npm run mini:test` 通过后交由用户在微信开发者工具中确认，重点看：长分类名、新增分类、可选字段齐全的商品、搜索后分类高亮。
