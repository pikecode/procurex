# 页面与交互详细设计

> 版本：v1.0 详细设计评审稿，2026-09-24
> 基线：[需求 v1.4](./requirements.md)、[已确认架构](./architecture-design.md)
> 配套：[接口设计](./api-design.md)、[数据库设计](./database-design.md)
> 状态：页面结构与交互规格，含低保真布局；尚未制作或实现高保真页面。

## 1. 设计目标

门店快速订货和收货，采购集中处理分配及资金阻断，供应商清楚看到待发和差异，财务能从总额追到每笔来源。首屏进入角色工作界面，不设置营销首页。

Web 使用紧凑导航、筛选条、数据表和必要的详情抽屉；小程序使用商品列表、分步确认及固定底部操作区。履约、门店付款、公司向供应商结算分别显示，不能以一个“已完成”代替全部状态。

本稿的页面编号供接口、任务和验收引用。界面排列属于本轮评审内容；结算方式、价格和权限规则沿用已确认需求，不因设计稿改变。

## 2. 角色入口与导航

### 2.1 Web 管理后台

| 角色 | 默认进入 | 导航 |
|---|---|---|
| 采购 | W01 采购待办 | 订货处理、订单、商品、供应商、订货模板、价格、统计、利润 |
| 供应商 | W03 待发货 | 自己订单、待补发、收货差异、商品（只读）、账单、统计 |
| 总部财务 | W07 财务工作台 | 门店账户、充值、清账、门店应收、供应商应付、直接账期查询、调整单、资金流水、利润 |
| 管理员 | W01/W07 按最近工作入口 | 以上管理功能、门店、账号权限、审计与任务 |

门店及门店老板/财务首版以小程序为操作入口，不凭后台框架默认增加 Web 业务范围。供应商与采购小程序的必要处理能力与后台一致。

## 4. 门店订货与订单

### 4.1 S01 可订商品

顶部显示当前门店、订货日期和搜索；左侧或顶部分类筛选，商品列表显示图片、名称、规格/销售单位、门店销售价、起订量、订货倍数和数量步进器。品牌、储存条件在商品详情显示。底部固定购物清单数量及金额。

商品只来自当前有效模板。价格、数量控件占用稳定空间，金额变长不挤压操作。无模板时展示“暂无可订商品”，不显示全商品库；商品无法分配或没有有效价时不能加入清单。

门店不选择供应商和支付方式；清单可展示系统拟分配供应商及自动匹配方式供核对。采购代下单先选择门店，再使用该店目录和同样的校验，不借代下单绕过模板。

### 4.2 S02 订货确认

显示门店、收货地址、订货日期，按拟供应商分组展示商品和金额；底部展示储值应扣、可用余额、缺口及挂账可用额度。后端报价预览决定本次显示金额。

| 场景 | 页面反馈 | 提交结果 |
|---|---|---|
| 储值足额 | 正常显示应扣金额 | “提交订货单”，成功待采购确认 |
| 储值不足 | 显示实际缺口，仍保留提交按钮 | 成功页显示“已提交，待补足”；不是错误页 |
| 挂账超额 | 显示超额与联系财务信息 | 阻止提交，不改成储值支付 |
| 预览后价格变化 | 列出变化商品和新金额 | 用户重新核对后再次提交 |
| 点击后断网 | 操作区显示“正在确认提交结果” | 按原幂等键查询，不让用户连续生成新单 |

成功后清空本次已提交草稿；未成功保留购物清单。储值不足的订单不得在成功页显示“已推送供应商”。

### 4.3 S03 订单列表和详情

列表分为待采购、待收货、已完成、已取消，并提供资金状态筛选。每行显示订货单号、日期、总额、采购状态及执行进度，例如“2 家供应商，1 家已完成”。

详情包含原始商品、采购调整记录、执行单列表、按批次发货/收货轨迹、自动结算方式和门店资金记录。门店看到销售价，不出现供货价、公司利润或公司向供应商的银行付款资料。

取消或减量记录同时显示货款调整及退款/额度释放结果。已完成但仍待补款，保持两个清晰状态：“收货完成”“待补款”，不改回待收货。

### 4.4 S04 按批次收货

入口必须指向具体发货批次。标题显示供应商、原执行单号、首次/第几次补发、发货日期；物流时显示该批次单号。每行显示发货量和实收输入，默认实收等于本次发货量。

上传收货凭证后提交。数量有差异时按钮文案为“提交收货差异”，结果为“待供应商处理”；无差异则为“确认收货”，是否整单完成由所有批次与待补状态共同决定。

供应商退回后，页面显示上次数量、退回原因、本次待核对值；提交生成新的收货版本。历史查看入口保留，但累计实收只显示当前有效版本，不让门店手工改累计总数。

```text
[选择行]   [...]    [...]       ...       ...       ...
```

这是信息布局，不是最终视觉稿。表格提供批选和分类筛选；长商品名称换行，数量与金额列固定宽度，底部操作区不遮挡最后一行。

### 5.2 编辑和按分类分配

采购可增删商品、调整数量，新增仍校验该门店可订范围。保存后更新金额、结算匹配和资金差额；保存不等于确认推送。

批量分配弹层显示已选商品、目标供应商，以及每行是否可供货。不合格时明确列出商品，整批不应用；用户修改选择后再提交。仅一个供应商的商品自动拟分配，多个则按模板优先级。

资金不足时“确认并分配”禁用并显示缺口，保留“保存修改”和查看门店联系方式；采购通知门店后，刷新资金再确认。即使按钮启用，服务端仍可能因并发扣款拒绝，页面保留订单并更新缺口。

### 5.3 拒单与重新分配

采购拒单需填写原因，确认弹层展示将退还的储值或释放的挂账额。供应商拒单到采购“待重分配”列表，显示原供应商、原因、待处理商品及其他供应商进度。

选择新供应商时，已在同次订货首次发货的目标标记不可选并说明原因。允许改分配或取消对应商品；重新匹配结算和价格，资金校验通过后才推送新分配，不影响其他正常执行单。

已确认订单因历史涨价等出现差额时，在详情提供“重新校验资金”动作，调用 O11。它与待确认订单的“确认并分配”分开，避免充值后没有补扣入口，或重复拆单。

### 5.4 S09 采购小程序

待办队列、编辑商品、分类批选、分配、资金缺口、确认/拒单、拒单重分配与 Web 一致。小屏按商品行展开价格和供应商信息，批选后底部显示数量和“分配供应商”操作，不挤成横向多列小字。

## 6. 供应商发货与差异

### 6.1 W03 / S06 发货

订单页只显示本供应商商品与供货价。发货表单包含：固定配送方式、本次发货量、永久减量、剩余待补量、物流单号（物流配送时）、运费。

本次少发与永久减量使用分开的操作。默认减少本次量保留待补；永久减量/移除需显示其货款调整，不能仅让供应商输入“2”而猜测原 3 件中的剩余 1 件是否取消。

首次发货提交前展示本次商品、运费和待补数量。补发从已有待补列表进入，最大可发量由缺口决定，不提供新增商品。配送方式为供应商唯一配置，不能在发货表单切换。

| 异常 | 页面处理 |
|---|---|
| 运费开关关闭 | 不提供金额输入，显示 0 |
| 补发额外运费 | 先提交费用确认，显示“待采购确认”，获确认后选择该费用记录 |
| 门店资金阻断 | 提示“待采购处理资金差额”，禁用发货；不泄露余额金额 |
| 版本过期/已经发货 | 刷新批次，不生成第二次发货 |
| 提交成功通知未送达 | 发货结果仍成功；订单列表可查，不要求再次提交 |

供应商未发货拒单填写原因，成功后不能继续操作该旧分配。其他供应商订单不出现在本账号页面。

### 6.2 W04 / S07 差异处理

详情显示门店、商品、本次发货、门店实收、差异、凭证和联系方式。三个清晰动作：

1. “安排补发”：显示待补量，生成待补项；进入补发表单后实际确认发货，原订单号保持不变。
2. “退回门店核对”：填写原因，回到门店收货入口，历史差异保留。
3. “同意实收数量”：展示最终有效数量及本供应商货款变化，提交后调整应收。

供应商不看到门店销售价差额。门店差异页只有进度和重新核对入口，不能替供应商选择三个处理结果。

跨期补发页同时显示本次发货日期、原归属周期。价格显示原单当前有效价格；如历史生效改价已依法适用，在变更记录可追溯，不把补发当天价格当作新报价。

## 7. 模板、商品与价格管理

### 7.1 W05 资料维护

商品编辑包含 SRS 全部商品字段；采购单位默认不启用，启用后只出现一组换算。起订量和倍数默认 1；商品图片预览提供 1:1 裁切，大于 2M 先压缩。供货价编辑进入版本化改价，不作为普通商品保存字段静默覆盖。

供应商编辑分为联系资料、供货商品、配送结算、银行开票信息。配送二选一、结算四选一、周期四选一。供货商品支持按分类选择，删除供应商提示解除当前关联且历史保留。

分类只允许二级；品牌和单位使用中不可删除。供应商账号进入相同资料只读投影，无保存、改价、删除和基础配送配置入口，接口同样拒绝写入。

### 7.2 W06 模板

模板页分“基本信息”“适用门店”“商品与供应商”“结算覆盖”。商品供应商按优先级排序，销售价按模板+商品+供应商维护。一个门店已有其他有效模板时不可勾选，并显示所属模板名称给有权采购。

结算覆盖以供应商为行，“使用供应商默认”作为继承模式；覆盖时再选择结算方式。展示当前实际匹配值及来源，不在每个商品行重复创建独立结算配置。

复制先确认新名称，不复制门店；删除提示将解除当前门店关系，新下单需重新绑定，历史订单不受影响。

### 7.3 W06 / S10 快速改价

选择价格范围和新单价，生效时间分为“立即”“指定时间”，指定时间可选过去或未来。按服务器时区显示；原因必填。直接账期需同步修改关联两价时，同一表单提交两者。

```mermaid
flowchart LR
    A[选择价格与生效时间] --> B[查看影响预览]
    B --> C[核对并发布]
    C --> D[版本已发布 / 重算处理中]
    D --> E[成功明细与失败明细]
```

影响页展示未完成订单数、已发货未完成数、销售或供货差额、预估资金缺口。已完成订单显示不受影响的规则结果，不提供强制追溯入口。

发布成功与重算完成分别显示；部分任务失败可以查看失败订单及重试状态，不要求重新发布同一个价格来触发重试。预览金额可能变化，提交返回实际版本与任务，不把预览当锁定报价。

## 8. 财务页面

### 8.1 W07 门店账户与充值

列表列出门店、储值余额、挂账授权、累计发生、未清、剩余。累计发生和当前未清分列，清账后累计不下降。编辑额度不能低于当前占用。

充值侧栏包含门店、业务日期、金额、收款账户、备注和图片凭证。操作人和录入时间系统生成。确认后返回充值单号、余额变化和关联流水；不显示“订单已自动确认”。门店端只能查看充值记录，不能自行修改余额。

### 8.2 W08 清账

选择门店后，只列该店挂账未清来源，可按日期和供应商筛选。批选底部显示笔数及合计；上传凭证、选择业务日期后点击“确认清账”。

操作结果展示独立清账单，包含明细、金额、日期、操作人、凭证和关联流水。金额在提交前发生变化时返回选中项差异供重新核对；不能悄悄清掉其他未选订单。

```text
账单详情：来源订单 / 商品明细 / 付款记录 / 调整记录 / 修订记录
明细选择框  来源订单  商品额  运费  待核对  可登记金额
                                  [付款登记] / [确认收款]
```

四个入口根据角色裁剪。门店看到自己的销售价账单；供应商只看到自己的供货价总单、分店单及直接往来，不出现公司利润。财务可在明确标注口径后切换，不能让同维度的销售价和供货价两张单长得无法区分。

供应商总单可进入各门店分单，分单能返回总单。两入口付款后同步刷新相同来源的已付与未付，不把分店单设计为再付一次的独立付款池。

付款登记先选同付款方、收款方的可付明细；不同供应商按组展示并分别登记。提交后为“待收款确认”；由收款方确认才变已结清。公司账期门店应收未结清的对应应付行不能登记公司付款，并能查看阻断来源。

### 8.4 W10 调整与差额

调整页固定展示原订单、原账单、原交易周期、差额结算周期、正负金额和原因。已结清原账单可跳转查看但不可编辑。负调整显示“待抵扣/返还”，不能仅显示负的未付后自动视为处理完成。

抵扣选择同双方主体和通道的目标应付/应收；没有后续采购可登记线下返还及凭证。状态变更需对应真实核销或返还确认；付款中途金额下降形成的多付款与普通少付分别展示。

## 9. 报表、消息与系统状态

报表表头注明日期口径：订货金额/数量为完成日，利润为首次发货日且仅完成订单，结算为原周期，流水为发生时间。利润显示商品收入、商品供货成本、差价、运费独立列，不称净利润。

商品数量查询限制最大 3 个月；空数据展示无记录，不用虚构示例金额。导出进入任务列表，包含筛选条件、生成时间、状态和下载；失败有可理解原因。权限被撤销后下载不可继续。

消息点击定位业务单据且重新鉴权；站内消息作为订单列表之外的提醒，微信消息发送失败不影响业务单存在。任务页区分“发布成功”“处理进行中”“部分失败”“完成”，避免只用一个成功提示掩盖批处理失败。

## 10. 统一交互状态和可用性

| 状态 | 统一处理 |
|---|---|
| 加载 | 保留布局尺寸、表头和已有筛选，关键操作禁重复点击 |
| 空列表 | 显示当前筛选无记录；有权限的资料页提供新增入口 |
| 请求失败 | 保留输入与选中项，可重试；不把失败显示成空列表 |
| 版本冲突 | 标明已被处理，刷新服务端结果，保留用户输入供对比 |
| 操作结果不确定 | 按原幂等键查结果；禁止提供会新建交易的盲目重试 |
| 会话失效 | 回登录，返回后恢复非敏感草稿；不自动执行旧财务命令 |
| 无操作权限 | 不显示写入按钮；服务端仍验证；访问无权对象返回不可访问 |
| 文件失败 | 每个文件单独重试；全部必需凭证验证完成才允许提交 |
| 停用资料 | 历史仍可查；新订货/新分配不可继续使用；已有履约按流程完成 |

Web 常用筛选保留在路由参数，返回列表恢复页码与筛选；小程序回到订单列表刷新刚操作单据。表格金额右对齐且固定精度，长名称换行。页面在窄屏、软键盘打开和底部安全区下不得遮住提交按钮或必填输入。

工具动作用标准图标和提示，模式用分段选择，二元配置用开关，数量用输入/步进器，命令用明确动词。键盘焦点可见、表单有标签、错误不限于颜色表达。业务确认弹层仅用于拒单、资金及影响范围等关键操作，不增加通用审批。
