# 0923 需求复核与执行方案

依据：用户提供的“需求审阅0923”图片；本轮新要求优先于此前冲突的模板支付方式配置。

## 业务规则

1. 门店下单不选择支付方式，每个供应商只有一种结算方式。仅供应商账期、公司账期需要周期。2026-10-09补充：模板可按门店和商品涉及的供应商覆盖结算周期，优先级高于供应商默认；不允许覆盖结算方式。未覆盖则继承供应商默认周期，移除门店或供应商后清理对应覆盖，复制模板不复制门店及其周期。已有订单保留结算快照，不批量迁移。储值、挂账不展示周期，数据库兼容字段使用IMMEDIATE，不作为账期规则。
2. 发货时必须确认配送方式，默认使用供应商资料中的自配送或物流。选择物流时可选填物流单号；每次发货保存配送快照，供应商后续资料变更不影响历史单据。
3. 充值、销账必须上传至少一张图片凭证，最多五张。服务端验证上传完成、图片类型、当前操作人和单据用途。历史无凭证记录仍允许查询，不补造凭证。
4. 供应商可以只读查看自己关联的商品，不可编辑商品、价格、供应商资料或支付方式。采购负责基础资料和分配规则；公司财务负责充值、挂账额度、销账和公司财务查询。
5. 订单履约状态与结算状态分开。账期和挂账订单下单后未付款不代表不可发货；未结算指账期或挂账尚未清偿。储值支付按既有冻结、收货扣减规则执行。
6. 门店提交少收数量，供应商核对后选择补发、退回或认可。门店不可替供应商处理差异。
7. 价格使用首次发货时间作为有效价格基准。正常后续生效的价格不影响该订单；追溯生效时间覆盖首次发货时间时，通过现有价格调整及审计机制重算，不删除原单据。
8. 挂账剩余额度 = 挂账额度 - 挂账未销账占用金额；累计挂账金额只作历史统计，不参与剩余额度计算。

## 实施顺序

- 第一项：统一供应商结算来源，移除模板支付方式操作入口，并阻止继续维护模板结算覆盖。
- 第二项：增加发货配送方式快照、接口校验及后台和小程序控件。
- 第三项：充值、销账图片凭证前后端强制校验。
- 第四项：复用已有供应商专用商品只读查询和小程序个人资料中的供货商品入口，验证数据范围及价格可见性。
- 第五项：整理状态文案，复核差异、价格调整与挂账公式。
