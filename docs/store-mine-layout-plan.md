# 门店页「我的」排版优化：落地文档

制定日期：2026-10-11。范围限于 `apps/miniprogram/pages/store/index.wxml` 的 `mine` 视图与配套样式，不改接口、权限与业务规则。

## 一、现状

门店页 `mine` 视图由两块构成，且两块在同一屏内是割裂的：

1. 第 90 行的主区块：身份卡 → 收货信息 section → 一个装了三个按钮的 section（门店资料 / 刷新门店资料 / 退出登录）
2. 第 92 行：独立的「账户与账单」入口块，游离在主区块之外

对照其余三个角色可见此页是唯一的异类：供应商、采购、财务均为「身份卡 + 功能菜单列表 + 退出」的组合，门店页则是「身份 + 信息块 + 纵向按钮堆叠」，视觉上与其他角色不一致。

具体问题：

### D1 「刷新门店资料」与「门店资料」语义不同却并列

前者是动作，后者是跳转去向。两者同处一个纵向按钮列表，管理员无法区分"点了会去哪"和"点了会做什么"。

### D2 收货信息以整块 section 呈现，缺少进入动作

收货地址与联系人属只读信息，但当前只以文字段落呈现，未纳入功能菜单体系，与其他角色的列表式条目不一致。

### D3「账户与账单」入口游离在主区块之外

它位于第 92 行独立的 `wx:if` 块中，与 mine 主区块不共享父级，后续调整 mine 结构时极易漏改，也是此前遮挡类问题的来源。

### D4 退出登录与普通操作同级

退出与「门店资料」同处一个 section，仅靠 `danger` 底色区分层级，属不可逆操作却未与常规操作分离。

## 二、方案

统一为「身份卡 → 功能菜单 → 次要动作 → 危险操作」四段，与其余角色保持一致的结构语言。

### O1 收货信息并入功能菜单

由独立 section 改为菜单条目，主文案「收货信息」，副说明显示地址与联系人（`广东省深圳市南山区测试路1号 · 测试店长 13800000000`）。信息不丢失，但获得明确的列表位置与进入暗示。

### O2「账户与账单」并回主区块

把第 92 行游离的入口块移入 mine 主区块的 `<block>` 内，作为菜单条目，消除割裂。

### O3 刷新动作与菜单分离

「刷新门店资料」移出功能菜单，改为菜单下方的独立次要按钮。它是动作而非去向，与菜单条目不属同类。

### O4 退出登录独立成块

与其余操作分离，保持 `logout-button` 的危险色，形成明确的操作层级：可逆操作在上，不可逆操作在下。

### 保留项

`components/test-context` 挂在 mine 视图上是**测试工作台的入口**，五个角色页面均如此，且其为文档流内的条块（非浮层）。本轮重排**必须保留该组件**，否则测试角色切换失效。其位置保持在 mine 内容最上方。

## 三、不做的事

- 不改其他三个角色的 mine 视图。本页验证通过后再推，本轮只改一处以便比对效果。
- 不改收货信息的取数逻辑（`receiptAddress || address` 的回落保持原样）。
- 不引入新页面或新接口。
- 不改 `openProfile`、`loadWork`、`logout`、`changeView` 的既有行为。

## 四、风险

- O1 将地址与联系人合并为副说明后，长地址加长姓名可能在窄屏换行，需确认 `.account-menu-item` 的副文案截断表现。本轮不主动加截断，先看实际效果再定。
- O3 将刷新移出按钮组后，其 `loading` 态仍需保留，避免刷新中无反馈。
- 重排涉及 mine 区块整体结构，需确认 `components/test-context` 未被误删，且 `mini:test` 中依赖 mine 结构的断言仍然成立。

## 五、验证

`npm run mini:check` 与 `npm run mini:test` 通过后交由用户在微信开发者工具中确认，重点看：菜单条目的副说明是否可读、长地址换行是否可接受、刷新按钮的 loading 态是否正常、测试工作台入口是否仍在。
