# 服务器场景验收数据

更新：2026-10-12。执行结果以本页末尾及私有 manifest 为准。

## 执行边界

- 目标为 `https://pr.moshuo.fun` 的服务器测试资料，不清理本地数据库。
- 先备份数据库及附件，再按明确的测试编码、上轮同步 manifest 清理。非测试门店、供应商、模板、订单及管理员保留。
- 测试关系与非测试订单交叉引用时中止清理，不使用 `TRUNCATE`、禁用外键或整库覆盖。
- 旧测试账号禁用并改为历史名称，保留操作人和审计；常用账号名重新分配给本次验收数据。管理员密码不变。
- 新账号通过用户管理接口创建，使用真实角色和数据范围。仅部署初始化使用一个限时管理员会话，结束后删除；各业务步骤使用实际账号登录所得会话。
- 下货单、采购确认、改派、拒单、发货修订、收货、差异处置、补发、充值、销账、付款均通过业务 API 操作，不直接插入状态和金额。
- 凭证为明确标记“验收专用”的测试图片，上传、绑定、权限、预览均走真实文件接口；测试资金不代表实际银行交易。
- 不宣称有限样本覆盖所有并发、午夜、跨月、压力或浏览器/真机交互。这里列出可人工复验的功能场景；自动测试及真实微信验收是独立证据。

### 推荐顺序

1. 使用 `store1` 查看订货、下货单与待收货列表；用 S06 收货、S09 选择差异处理、S11 收补发，或从新下货单开始完整流程。
2. 使用 `buyer` 处理 S01、S03、S05 和 C03；用 `supplier2` 处理待发货及 S10 补发，`supplier5` 可处理备用供应商订单。
3. 使用 `fin` 查看充值/销账凭证，处理公司付款；`store2/store3/store4` 分别验收挂账、公司账期、供应商直结，供应商对应 `supplier3/supplier1/supplier4`。
4. 使用 `store_fin1..4` 验收门店财务只读；`follower/region/region_fin` 验收仅授权储值和挂账两店。
5. 使用 `store_low` 给 U01 所属门店真实充值后继续流程；`store_limit` 提升额度后重新提交；`store_empty`、`store_disabled`、`disabled_user` 验收限制。

开始人工操作后，基线金额和单据状态会变化，不能再将初始验证脚本的精确金额断言当作实时结果。旧登录态已撤销，请退出后使用本次验收密码重新登录；服务器管理员仍使用原密码，production 下不启用身份模拟。

### 复现说明

清理脚本默认只输出候选记录并回滚，必须先备份、审查清理预览，再明确传入 `--apply`。重建前应归档旧的私有 manifest/access，不能拿旧 manifest 在已清理的库上继续生成。

生成脚本使用私有 manifest 对成功步骤做检查点；失败可继续执行，不重复充值、付款、收货或下单。图片生成需运行环境提供 fontconfig 与字体（本轮安装了 DejaVu 字体）；不需要为了生成数据修改线上业务图片。不要直接运行 `reset-local-test-data.mjs` 清理服务器。
