# 下货单采购确认与资金核验

最终口径：2026-10-16。取消此前独立财务审核方案，保留文件路径供已有链接使用。

## 流程

门店提交下货单 → 采购核对商品、数量和供应商 → 资金核验 → 确认并生成供应商订单 → 发货 → 收货 → 结算。

门店资金不足可以提交；采购首次确认前可增减数量、增删模板商品，保存更新原单号。采购也可单独保存调整，资金不足不阻止保存。确认时储值和挂账均须足额，否则整笔回滚，不确认、不部分生成订单。财务负责充值、调整额度及既有财务业务，不再审核下货单生成订单。充值/调额不自动生成订单，采购须重新核验确认；储值在收货后实际扣款。

## 页面

商品清单后展示资金核验：储值所需、本单可用、待充值金额；挂账所需、本单可用、待补挂账额度。可用金额包含本单已占用金额，不重复扣除。两类缺口分别显示，不能合称充值金额，均保留两位小数。账期结算不要求储值或挂账资金。

提供重新核验、保存调整、确认并生成订单。调整商品后旧核验失效，资金不足给出联系财务的明确提示。前端禁用确认入口，后端也必须校验，避免绕过页面。

小程序资金区采用支付方式、本单所需、本单可用三列对齐展示；仅非零缺口进入警示区，分别列待充值金额和待补挂账额度。资金充足显示可生成订单，不重复展示历史待审核提示。不改变金额计算和确认拦截规则。

## 接口与兼容

- GET /purchase-requests/:id/confirmation-preview：实时资金分组统计。
- POST /purchase-requests/:id/confirm：直接生成订单，返回 CONFIRMED 和 supplierOrderIds。
- POST /purchase-requests/:id/confirm-adjusted：调整与确认同一事务，失败不保留部分调整。
- PATCH /purchase-requests/:id/items：单独保存采购调整，允许资金不足。
- PATCH /purchase-requests/:id/store-items：仅本店厨政经理在采购首次确认前修改，要求版本和幂等键。
- 原财务审核入口撤下，finance-approve 和 finance-return 均拒绝旧审核操作。历史 PENDING_FINANCE 单据由采购待办接续处理，不重建历史订单。

确认权限仅 ADMIN/PURCHASER/PURCHASE_FOLLOWER；跟单限制授权门店。幂等键、版本和事务锁防止重复生成及重复占用，操作记录采购确认审计。
