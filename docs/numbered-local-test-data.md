# 本地编号测试数据

本套数据仅写入本地数据库，名称使用连续编号。商品、供应商、门店、模板和用户之间的关系如下。没有预置订单，所有订单由实际下货、采购确认、发货及收货操作生成。

后台入口：`http://127.0.0.1:4174`。本地 API：`http://127.0.0.1:3114/api/v1`。

用微信开发者工具测试本套数据时，`apps/miniprogram/app.js` 的 `apiBase` 使用 `http://127.0.0.1:3114/api/v1`，并关闭合法域名校验。本机 `project.private.config.json` 的 `setting.urlCheck` 要为 `false`，否则会覆盖公共配置并拦截本地HTTP请求；修改后重新打开项目。这批账号和数据仅存在本地数据库，服务器数据独立。

## 编号规则

- 名称为门店1～10、商品1～15、供应商1～5、模板1～6。
- 商品1～12的商品参考价为编号乘10元：商品1是10元，商品2是20元，以此类推。
- 商品1～3主供供应商1，商品4～6主供供应商2，商品7～9主供供应商3，商品10～12主供供应商4。
- 供应商5是商品2、商品3的备用供货方，同时关联下架验证用的商品13。
- 门店与供应商的供货关系由门店模板里的商品及其供应商配置形成。
- 商品参考价、供应商价格与模板销售价格分别保存。门店下货按模板中实际分配供应商的销售价格计算。

## 用户

本地测试账号的统一密码：`12345678`，包括 `admin`。初始化脚本保留已有 `admin` 的密码，不会覆盖它。

| 账号 | 显示名称 | 角色及数据范围 |
|---|---|---|
| `store1`～`store10` | 门店用户1～10 | 门店厨政经理，只能操作对应编号门店 |
| `storefin1`～`storefin10` | 门店财务1～10 | 查看对应编号门店的订单、账单和结算 |
| `supplier1`～`supplier5` | 供应商用户1～5 | 对应编号供应商的商品上下架、订单发货及对账 |
| `buyer1` | 采购用户1 | 采购经理，所有门店，后台资料维护和采购确认 |
| `buyer2` | 采购用户2 | 采购跟单，只授权门店1、2、3 |
| `fin1` | 财务用户1 | 总部财务，全部门店，充值、额度、销账及账期结算 |
| `fin2` | 财务用户2 | 区域财务，只授权门店1、2、3 |
| `region1` | 区域用户1 | 区域经理，只授权门店1、2、3 |

共30个新增账号，加已有admin共31个账号。账号、角色和范围都保存在数据库里。

## 初始化与验核

初始化脚本：`scripts/seed-numbered-test-data.mjs --apply`，仅允许本地专用数据库并要求业务数据为空，拒绝覆盖已有数据。

验核：`node --env-file-if-exists=.env scripts/seed-numbered-test-data.mjs --verify-only`。验核实际API登录、绑定范围、模板报价、单位换算、资金不足及不可订商品；不创建下货单或正式订单。本套基础数据初始化后的价格和余额已经过验核。

完整ID清单及验核结果：`var/private-files/numbered-test-data.json`。实际业务测试后余额与订单会变化，验核脚本的“初始状态”断言可能不再适用。
