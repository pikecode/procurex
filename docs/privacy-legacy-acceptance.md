## 角色合同与证据

| 模块/动作 | 允许角色 | 范围/隐私规则 |
|---|---|---|
| 商品/分类/品牌/单位、供应商与模板写 | ADMIN/PURCHASER | 其余角色拒绝；供应商仅读自身资料/目录，主数据写审计复用C5 |
| 门店/用户资料写 | ADMIN | 其他角色只读获准资料，不能用body伪造操作者或范围 |
| 下单/下单预览 | ADMIN/PURCHASER/STORE | 门店只能自身下单，STORE_FINANCE不能代下单 |
| 请求编辑/分配/确认/拒绝/资金重核、运费审核 | ADMIN/PURCHASER | 财务/门店/供应商不可操作采购 |
| 发货/预览、运费申请、供应商拒单、差异处理 | ADMIN/SUPPLIER | 供应商只能自身订单；缓存成功重放也校验当前范围 |
| 收货 | ADMIN/STORE | 门店只能自身发货单，门店财务及总部财务不能收货 |
| 充值/额度/清账、差额创建 | ADMIN/HQ_FINANCE | 业务角色不能修改公司资金；私有账户单据只给获准总部/所属门店 |
| 付款创建/预览/撤销 | ADMIN/HQ_FINANCE/STORE/STORE_FINANCE | 按付款方向及门店匹配；门店不能读公司对供应商成本付款 |
| 付款确认/拒绝 | ADMIN/HQ_FINANCE/SUPPLIER | 供应商只确认自己可见的采购/直结付款，不能读门店对公司销售付款 |
| 差额确认 | ADMIN/HQ_FINANCE/STORE/STORE_FINANCE/SUPPLIER | 参与者及退回方向检查，不能确认他方单据 |
| 订单状态只读 | ADMIN/PURCHASER/HQ_FINANCE及对应门店/供应商 | HQ_FINANCE可跨门店读申请、订单、发货状态；不扩大其采购/履约写权限 |
| 报表/导出 | 六角色 | 范围强制；门店无成本，供应商采购金额口径，业务角色无利润报告 |
| 文件创建/上传/完成 | 六角色除SUPPLIER | 服务继续限制用途/owner/token/READY和单据关联；下载需原上传者、获准总部或合法参与者 |
| 命令审阅/价格有证据关闭 | ADMIN | 非管理员拒绝；其他未知命令不能借价格接口解除 |

## 本批实现

- 补齐11类控制器的BusinessScopeGuard：四类账单、运费、旧充值/清账、供应商、文件、报表、导出。业务角色缺少范围或范围类型错误时拒绝访问，不能因空过滤条件获得全局数据；总部角色保持原权限。
- 门店/门店财务的商品目录、采购请求、预览、订单发货与收货响应递归移除采购成本/利润。保留不含金额的supplyPriceVersionId，双价格版本批准、过期检查和原键重放继续有效；总部角色不删字段。
- 供应商金额报表及CSV按采购成本计算，amountBasis由服务端认证范围决定，客户端不能覆盖。历史供应商销售口径缓存导出不再提供列表、状态、下载或重试；未补写历史文件或数据。缺少报表日期的历史订单不纳入该日期口径，不伪造日期。
- 付款读取及附件参与者授权同时检查付款方向：门店不能读COMPANY_TO_SUPPLIER，供应商不能读STORE_TO_COMPANY；门店付款预览拒绝供应商应付及供应商侧调整项，总部及正常直结方向保持可用。附件原上传者及总部原权限保留。
- 四个保留无幂等键的旧入口（价格发布、价格任务执行、采购明细替换、采购供应商指派）将业务及审计放入同一数据库事务。审计取会话操作者，标记LEGACY_HEADERLESS；不伪造幂等键或CommandRecord。带键入口原契约不变。

## 支持边界

- 无键调用丢失响应后无法按原键精确找回；必须先读业务事实，不能自动重做。不能将价格专用已证明回滚的人工关闭机制推广到其他未知命令。
- 旧充值/清账允许省略附件的兼容边界仍存在；正式Web要求凭证不等于所有旧API强制凭证。
- 本次补齐固定C6/C7剩余写动作拒绝矩阵及安全操作手册，整项关闭；不追加任意角色排列或通用自动补偿作为新的交付要求。未来更改角色合同须更新启动库存及回归。
