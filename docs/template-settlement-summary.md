# 订货模板结算配置交互：总结文档

完成日期：2026-10-10。对应落地文档 `template-settlement-plan.md`。

## 一、重要前提：代码已非本轮开始时的状态

核对过程中发现结算配置已被重构：账期已从商品编辑器内移出，成为独立的 `settlement` 弹窗，保存走 `PUT /templates/:id/settlement-cycles`，与商品价格配置完全分离。原「商品展开行内账期横向矩阵 / 门店折叠分组」方案已不存在。

因此本轮**未沿用落地文档中的 O1 描述**，而是基于重构后的现状重新实现——目标是"账期以门店为主"，与用户诉求一致，落地方案（门店分组折叠）不变，只是起点不同。

同时**撤回一条此前的错误判断**：曾认为 `dirty()` 用 `getFieldsValue(true)` 全量比较会误报脏。重新核对后确认 `initial.current` 在 `setFieldsValue` 之后计算，开窗时两者一致；且"选择等于供应商默认周期时不写入 rows"是正确行为，无实际变更本就不该判脏。**该处不修改。**

## 二、改动范围

仅 `apps/admin/src/pages/Templates.tsx` 的 `settlement` 渲染块，与 `TemplateProducts.css`。未改后端接口、数据模型与账期业务规则。

## 三、逐项完成情况

### O1 结算配置改为按门店分组（对应 D1、D4）

结算弹窗由一张平铺表格改为 `Collapse`，每个绑定门店一个面板：

```
适用门店 3 个：测试门店A、测试门店B、测试门店C

▼ 测试门店A                      2 / 4 已设
  供应商            结算方式      供应商默认周期  本门店结算周期
  华东食品         公司账期结算   月结          [月结 ▾]
  联合供应         供应商账期结算 周结          [周结 ▾]
▼ 测试门店B                      0 / 4 已设
  ...
```

实现要点：
- `storeGroups` 预先按门店聚合，每组含门店名、该门店的账期类供应商及其当前周期、已配置数量。
- 面板标题右侧显示 `已设 / 总数` 进度，未配完时为橙色（`.is-pending`），配完转灰，一眼看出哪些门店还欠配置。
- 同一门店的供应商连续排列，消除了原平铺表中"跨行找同一门店"导致的错配可能。
- 门店为一级纵向结构，任意门店数都不产生横向溢出。
- 默认展开全部门店；超过 12 个门店时默认只展开前 3 个，避免信息过载。
- 移除了原表格的分页——门店即分组单位，面板内数据量等于单个门店的供应商数，通常很小。

### O2 说明被排除的非账期供应商（对应 D2）

新增 `immediateSuppliers`：模板内但结算方式为储值/挂账的供应商。存在时在弹窗顶部显示警告条，列出名称并说明"固定即时结算，无需设置账期"。

这解决了此前"商品页配了 5 个供应商、结算页只看到 2 个"却无任何解释的困惑。

### O3 结算弹窗内说明门店来源（对应 D3）

弹窗顶部固定展示当前适用门店数量与名称列表。未绑定门店时，该提示条直接给出引导文案"尚未绑定门店，请先在「编辑」中配置适用门店"，替代了原先含义模糊的"暂无适用门店"空状态。

**按落地文档中的风险评估，本项采用只读展示而非直接编辑**：`save()` 的 `settlement` 分支只提交 `rows`，若在此处允许改门店而不随请求落库，会出现"改了门店却没保存"的误导。要在结算弹窗内直接编辑门店，需将该分支改调 `/configuration`，涉及接口语义变更，不在本轮范围。

另补充：存在账期供应商但无门店时不显示折叠面板（门店为空则无从配置），由顶部提示条承担引导。
