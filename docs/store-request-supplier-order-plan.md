# 下货单与供应商订单流程

## 2026-10-16 门店修改下货单

门店提交后、采购首次确认前，厨政经理可以修改原下货单：增减商品数量、添加或移除有效模板商品，至少保留一种商品。使用原下货单编号，保存后重新计算销售金额及储值/挂账占用，资金不足仍可保存。采购确认后锁定；财务退回仅由采购调整，不重新开放门店编辑。门店不可自行改价或指定供应商。小程序入口为下货单详情“修改下货单”。本节替代旧文档中门店提交后不可修改的说明。

## 当前确认口径（2026-10-16）

最终采用“门店提交下货单 → 采购资金核验并确认 → 生成供应商订单”。资金不足不阻止门店提交及采购保存调整，但阻止采购确认生成订单。财务充值/调额后采购重新核验，不再设置独立财务审核。历史 PENDING_FINANCE 单据由采购待办接续。详见 [采购确认资金规则](./purchase-request-finance-review.md)。

## 当前确认口径（2026-10-14）

本节覆盖下方历史方案中“门店订单列表以订货单为唯一主记录”等不一致要求。历史实施记录保留，不代表本节页面改造已经完成。

### 单据归属与生命周期

- 下货单由一个门店发起，是采购确认前的商品需求；“订货单”是历史门店端称呼，后续统一称“下货单”。采购确认前不向门店展示拟分配供应商。
- 采购最终确认后，按最终供应商将该张下货单拆成正式供应商订单；一家供应商在该次确认中形成一张订单，不在提交或预览阶段提前生成。
- 一张正式订单只归属一个门店、一个供应商、一张来源下货单。一个门店和一个供应商都可以有多张订单；一个供应商可同时给多个门店供货，不存在“不能跨门店合作”的限制。
- 不将不同门店或不同下货单合成一张订单。一张下货单可以产生多张订单；拒单改派保留旧订单及来源关系，不能依据供应商数量推断历史订单总数。
- 生成正式订单后，门店、采购及供应商均围绕正式订单跟进发货、补发、收货、差异及结算。下货单保留用于来源追溯、采购调整记录、统计分析，不要求每次先打开下货单才能处理订单。
- 下货单汇总进度可保留，但不代替各正式订单的独立状态。单张订单完成不代表同源其他订单完成。

### 各角色展示

| 角色 / 页面 | 主记录与主要信息 | 来源信息 |
| --- | --- | --- |
| 门店订单页 | 正式订单；供应商名称、订单号、状态、商品摘要、销售金额 | 详情次要区显示来源下货单号，可查看本门店来源记录 |
| 门店下货记录 | 待采购确认、待补资金等未生成正式订单的需求；下货单号、商品、金额、提交时间 | 已生成的历史下货单可查询及追溯，不重复计入正式订单数量 |
| 采购待办 | 待确认下货单、拒单改派、运费审核，按业务对象区分 | 确认结果显示生成订单数量和正式订单入口 |
| 采购订单页 | 正式订单；门店、供应商、订单号、履约与资金状态、金额 | 来源下货单号可用于查询筛选、详情追溯和导出 |
| 供应商待办 / 订单页 | 本供应商正式订单；门店、订单号、状态、商品及供应商金额 | 不常驻来源下货单号，不开放整张下货单及其他供应商商品 |
| 财务 / 统计 | 以正式订单及有效账务事实统计；保留门店、供应商维度 | 输出来源下货单号用于关联，不把下货单总额与订单金额重复相加 |

- 保留现有底部导航；门店“订单”页内区分“订单”和“下货记录”，默认订单。提交下货成功进入该张下货详情并提示待采购确认，而不是冒充订单已生成。
- 正式订单详情以门店 / 供应商、完整订单号、状态及商品为主；来源信息置于次要区域。收货仍定位到具体订单下的发货批次。
- 同一张订单只展示自身商品；同源其他订单仅在有权限的来源追溯页查看，不混入订单商品清单。
- 正式订单查询支持订单号；有来源追溯需要的门店、采购支持下货单号查询。供应商主要按门店、订单号及状态查询。
- 单号完整展示，不再缩成日期加末四位；窄屏允许在单号区域换行，不挤压商品、状态及操作。不改变历史编号或生成规则：PR / SO + UTC 年月日时分秒 + 六位随机数，关联以数据库外键为准。

## 需求边界

- 门店提交的是下货单（PurchaseRequest），记录商品、数量及门店销售金额，不是供应商订单。
- 门店选品、提交确认和采购确认前的下货单详情不展示供应商、供应商联系信息或供应商分组。
- 系统内部保留模板首选供应商作为采购的初始分配，用于报价与资金校验，不代表已向供应商下单。
- 采购确认前可针对某个商品替换供应商，仅可选该门店模板中适用、当前可供货且有有效价格的供应商。
- 替换前展示销售金额、供应商金额变化；保存后按目标供应商对应的销售价格和供应商价格重新计算金额与资金。资金不足时不得生成订单。暂不新增门店二次审批流程。
- 替换供应商只修改下货单，不发送供应商订单。采购最终确认时，按最终供应商分组，一家供应商生成一张订单。
- 供应商只能看到分配给自己的正式订单；发货、收货、差异处理、结算继续针对供应商订单进行。
- 正式订单生成后不得使用确认前的换供应商接口修改；拒单等异常继续走现有改派流程。
- 确认、替换沿用版本校验、幂等提交、审计记录及角色权限。采购跟单不因此获得采购经理的供应商调整权限。

### 门店模板订货边界复核

- 一个门店只能绑定一个有效模板，一个模板可绑定多个门店。采购更换供应商必须限于该下货单所用模板的该商品供应商，且供应商启用、未归档、商品上架并有有效价格；保存事务内再次校验，不只限制页面候选列表。
- 门店商品目录及新下货单必须以当前绑定的有效订货模板为准，不允许回退到全量商品库；没有有效模板时禁止新下货。
- API 原有目录、报价和创建接口均执行该规则，创建事务内再次读取模板；此次没有改动服务端业务规则。
- 小程序收到无模板错误时，清空旧商品、已选清单及报价，隐藏订货底栏，提示联系采购配置有效模板。历史订单查看与收货不受影响。
- 已发送但结果不确定的下货命令保留原幂等键用于核对结果，不因为模板失效丢弃记录。
- 验证通过：144 项小程序测试、静态检查、TypeScript 构建和真实数据库 HTTP 测试（无模板目录/报价/提交均拒绝且无下货单，绑定后报价成功）。没有部署服务器。

# 订货确认金额展示补充（2026-10-13）

金额区统一使用“订货金额”。按本次结算金额展示：储值金额大于零才显示预冻结、当前可用储值及预计冻结后可用储值；挂账金额大于零才显示本次挂账、当前可用挂账额度及预计提交后剩余额度。余额及额度均为提交前值，剩余值为预览估算，不表示已经冻结或扣减。挂账示例：4631.16 - 290.50 = 4340.66。

资金不足时保留待补资金或额度缺口，不显示负数作为预计剩余。混合结算分别展示各方式金额；商品销售金额扣除储值及挂账金额后的账期部分统一标注“本次账期结算”，当前预览接口未细分公司或供应商账期。计算使用整数分，提交前报价或资金变化时重新生成摘要并要求再次核对。此次不改变结算方式、额度占用或扣款时点。
