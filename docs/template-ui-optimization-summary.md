# 订货模板交互优化：总结文档

完成日期：2026-10-10。对应落地文档 `template-ui-optimization-plan.md`。

> 历史总结说明：本文保留当次迭代结果。后续需求已将“商品统一门店销售价”调整为“每个供应商独立门店销售价”，并将账期配置迁至独立“结算配置”。当前规则见 `docs/template-current-spec.md`。

## 二、逐项完成情况

### O1 账期草稿回显（对应 D1）✅

**问题**：`cycleFor()` 只读 `detail.cycleOverrides`，即服务端已保存值。管理员在下拉中选择新周期后，值写入父组件 `cycleDraft`，但组件自身无任何处读取，界面不反映本次修改。

**改动**：`cycleDraft` 作为 prop 传入组件，`cycleFor()` 按「草稿 → 已保存 → 空」三级取值：

```tsx
const cycleFor = (storeId, supplierId) =>
  cycleDraft.find(row => row.storeId === storeId && row.supplierId === supplierId)?.settlementCycle
  ?? savedCycles.find(row => row.storeId === storeId && row.supplierId === supplierId)?.settlementCycle
  ?? '';
```

**验收对照**：选择周期后下拉立即显示所选值；切换商品再返回值保持；放弃修改关闭弹窗后回到已保存值。

### O2 门店数超阈值时布局降级（对应 D2）✅

**问题**：`minmax(150px, 1fr)` × 门店数，8 门店约 1400px，与 Modal 宽度冲突，且每个商品展开都需重新横向滚动、各行滚动位置独立。

**改动**：抽出 `renderCycleCell()` 与 `supplierRow()` 两个渲染函数供两种布局共用。

- 门店数 ≤ 4：横向网格，视觉焦点集中在一张表。
- 门店数 > 4：改为 `Collapse` 按门店纵向分组，默认展开前两个门店，每个面板内是该门店的供应商周期表（此时只有一列周期，不会横向溢出）。

**验收对照**：5 个以上门店不再横向溢出；任一门店周期可通过折叠面板到达。

### O3 移除独立"结算周期"弹窗（对应 D3）✅

**问题**：账期存在双入口，且旧入口有两个缺陷——`Form.List` 内直接 `form.getFieldValue` 绕过 `Form.useWatch` 导致切换门店不重渲染；结算方式列为二元判断，把储值/挂账供应商错误显示为"公司账期"。

**改动**：删除 `Mode` 中的 `cycles`、`cycleStore`、`initialCycles`、`cycles` 表单字段、`cycleChoices` 局部常量、操作列的日历图标及弹窗体，`Table` 与 `CalendarClock` import 一并移除。账期仅存商品展开行内一个入口。

**验收对照**：操作列不再出现"结算周期"图标；全部账期可在商品编辑器内配置完成。旧入口的结算方式错误展示随之消失——新矩阵改用 `modeLabels` 映射表，储值/挂账正确显示为"储值支付"/"挂账"。

### O4 主表价格列合并（对应 D4）✅

**问题**：旧界面把销售价放在供应商行上，容易误解为切换供应商会产生另一套门店售价。

**改动**：商品主行显示只读「参考销售价」和唯一可编辑「门店销售价」；供应商展开行仅显示各自供货价和按统一门店销售价计算的毛利。

**验收对照**：切换默认供应商不改变门店销售价；不同供应商可显示不同供货价和毛利。

供应商范围不再通过模板内下拉重复选择。新增商品和打开已有模板时自动继承商品管理中的全部有效关联供应商，模板内只保留首选供应商配置。

### O5 合并展开行内两张表（对应 D5）✅

**问题**：展开后供应商名在主表、供应商表、账期矩阵左侧三处重复；结算方式在独立列和"即时结算"占位中重复表达。

**改动**：合并为单张矩阵，每供应商一行，左侧为供货价和毛利，右侧为门店周期。结算方式降级为行内文字标签。首选切换的单选按钮直接内联到供应商名前。

**验收对照**：展开单个商品只呈现一张表，供应商名只出现一次。

### O6 反馈与适配完善（对应 D6）✅

- **负毛利标红**：新增 `MarginCell` 组件，毛利为负时红色加粗（`.template-margin-negative`）。同一组件用于主表与矩阵，口径一致。
- **未保存提示**：底部汇总条在有改动时显示「● 有未保存修改」。脏检查抽为 `itemsDirty()`，与关闭弹窗的确认逻辑共用同一函数，避免两处判断不一致。
- **占位降噪**：非账期供应商由整格灰色"即时结算"文字改为 `—` 加 tooltip 说明原因。
- **响应式宽度**：Modal 宽度由固定 `1400` 改为 `min(1400px, 94vw)`。

## 三、顺带修正

- 原「结算方式」列的内联三元判断抽为 `settlementModeLabel()` + `modeLabels` 映射表，与后端 `resolveSettlementTerms` 的账期判定口径对齐。
- `supplyPriceOf()` 统一读取供应商供货成本，模板销售价改为商品项级字段并校验最多两位小数。
- 模板保存时将同一销售价发布到所有关联供应商的模板价格范围，但不覆盖各供应商供货价。
- 移除供应商账期下销售价必须等于供货价的旧约束。
