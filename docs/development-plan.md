## 1. 交付范围与执行原则

首版交付门店订货、采购确认分配、供应商双端履约、门店收货与差异、储值挂账、周期结算、利润报表、权限及审计。第三方门店同步、在线支付、通用审批、库存/入库/出库继续排除。

按业务闭环交付，每个任务都包含后端、必要界面、权限及测试。详细设计先确认，再编写业务代码；当前已经存在的少量工程配置和依赖安装不视为业务完成，也不作为数据库迁移已执行的证据。

本计划确定任务、依赖、完成条件和验收责任，不复用旧版 95 人天/19 周作为承诺。人员投入、技术验证结果及上线条件明确后，再按本文工作包重估 `estimation.md` 和 Excel，保持两者一致。

```mermaid
flowchart LR
    D[详细设计确认] --> M0[M0 工程及技术验证]
    M0 --> M1[M1 身份、资料、模板价格]
    M1 --> M2[M2 下单、资金、采购拆单]

    M3 --> M4[M4 历史改价、账单与核销]
    M4 --> M5[M5 报表、通知及运营]
    M5 --> M6[M6 验收、恢复演练、试运行]
```

M1 建价格版本，M2 建资金和计价事实，M3 建首次发货周期；M4 完成其联动及正式结算界面。不能直到 M4 才设计金额及核销来源。文件上传、授权和审计从 M0/M1 起贯穿后续任务。

多人情况下可按已锁定接口并行 Web/小程序；涉及同一资金模型的后端任务按事务边界协作，不能各写一套扣款或计价实现。单人按依赖顺序完成，不用重叠甘特条假装同时投入多个人。

## 4. 每个工作包的完成定义

开发完成需同时具备：业务实现、实际数据库迁移、接口契约、角色字段隔离、页面异常态、审计与幂等、相关自动化测试以及必要文档更新。提交记录或“页面能打开”不能单独证明完成。

需求变化先更新基线和受影响设计，再改代码；具体版本、索引和页面组件细节由开发按既定规则决定，不反复让用户确认常规技术选择。新增业务能力或放宽 D4/D5 限制需要单独记录变更。

金融效果不可通过删流水修正；必须按已设计的冲销/调整命令进行。测试数据与正式数据隔离，不能为了测试改动其他项目数据库或客户真实账款。

### 5.1 标准数据集

| 数据 | 内容 |
|---|---|
| 门店 | A、B 分别绑定不同模板；C 无模板；D 停用 |
| 供应商 | X 物流、Y 自配送；每个供应商只有一种配送；X 半月结、Y 月结 |
| 商品 | P 可由 X/Y 供货；Q 仅 X；R 仅 Y；P 销售袋、采购包，1包=10袋 |
| 价格 | P 销售价12、供货价9；直接账期专用测试配置两价均9 |
| 模板 | A 对 X 覆盖储值，B 对 X 使用公司账期；另建挂账与直接账期独立测试场景 |
| 资金 | 各用例独立初始化期初余额和额度，避免串场；不能一个余额同时承担互不相关断言 |
| 角色 | 两门店账号、门店财务、X/Y供应商、采购、总部财务、管理员 |

### 5.2 标准金额

| 场景 | 断言 |
|---|---|
| 10件、销12、供9、运5 | 门店125、供应商95、商品利润30 |
| 首发10实收8，补2收齐 | 有效量10；销售125、供货95；物理发货12不重复计货款 |
| 实收8且供应商同意，无补发 | 门店101、供应商77、利润24 |
| 原125/95已结清，之后同意少收2 | 原账单冻结；差额分别-24/-18；交易有效总额101/77 |
| 独立未完成订单，原单侧账款100已结清，适用改价后总额先120再130 | 第一次调整+20，第二次仅+10；不是第二次再+30；两次发生时履约都尚未完成 |
| 储值100、订单500、充值400 | 下单不扣部分100；确认前余额500；采购确认扣500、余额0，只一次扣款 |
| 挂账未清1000，清选中300 | 未清700、剩余额度增加300；累计发生不减；独立清账单300 |
| 分店应付95与77 | 周期总单172；从任一入口核销95后，总单未付77，不能再核销同95 |

已结清未完成场景可通过发货后付款、收货差异仍待处理构造；不能为了测试历史改价而先把履约完成再强行改价。最终订单完成后始终不追溯价格。

## 8. 性能、上线与客户验收

SRS 的列表1秒、报表3秒、首屏2秒、下单200QPS、10万行导出10秒仍为待验证规划目标。建议用固定环境、明确并发和数据集记录 p50/p95/错误率，导出分别记任务受理与实际生成时间。不能把异步受理很快当作导出性能达标。

上线前核对：微信账号及域名、对象存储、TLS、生产数据库、备份恢复、权限账号、收款账户、期初金额、提醒阈值、监控接收人及发布回退方案。操作人分别承担开发自测、产品规则核对、财务验算和客户业务确认，可由小团队同人兼任但保留各项结果。

建议先选少量门店和供应商试运行，至少覆盖一种跨周期补发、一次充值清账及一个完整账期。试运行不是删除首版功能，只缩小使用范围验证数据。
