## 2026-10-06 储值扣款时点确认

本次用户确认优先于原图和旧版“下单即扣款”描述：充值增加储值余额；新储值订单下单时冻结，采购确认不扣款，供应商订单确认收货并完成收货差异处理后扣款。拆分后的供应商订单独立结算；未完成部分继续冻结。可用储值 = 储值余额 - 冻结金额。冻结不是支付，实际扣款后才记已支付和扣款流水。

减量、取消、拒单释放未扣的冻结金额；已实际扣款的历史订单仍按原规则退款或调整，不退款后重新冻结、不重复扣款。收货修订重新核对金额，差异未处理完不得提前扣款。充值不自动确认或推送订单。

门店销账（界面现称清账）是归还挂账欠款：减少挂账未清金额、恢复剩余额度，不减少历史累计挂账，不扣储值余额。与充值是两类不同资金操作。

### 1.4 架构评审确认的业务边界

以下为 v1.4 新确认口径，是正文相关规则的细化；正文此前使用“一般”“通常”等表述时，以本节明确约束为准。

| 对应决策 | 已确认规则 |
|---|---|
| D2 金额与数量 | 首版人民币；金额保留 2 位，单价和数量保留 6 位。商品行金额先四舍五入到分，再累加到订单/账单；商品差价利润展示为有效销售商品金额减有效供货商品金额，运费不计入，尾差按统一舍入口径解释 |
| D3 混合结算 | 同次订货的全部储值部分作为一组，足额整体冻结，不足不新增部分冻结；收货完成后实际扣款。挂账组独立校验并占用额度，挂账超额则整次提交失败且回滚。任一资金组未通过，采购不得部分确认、拆单或推送 |
| D4 拒单改分配 | 拒单退回采购后，可分给其他可用供应商，或并入同次订货尚未发货的目标执行单；目标供应商在同次订货中已有首次发货执行单时，不允许向其追加改分配商品，采购应选择其他可用供应商或取消对应商品 |
| D5 直接账期价格 | 供应商直接账期销售价与供货价必须一致；不形成公司同额应收应付，不计入公司商品差价利润 |
| D5 公司付款 | 公司账期对应门店应收确认结清后，才允许登记公司向供应商的对应付款；首版不开放特殊垫付例外 |
| D5 挂账额度 | 不允许将挂账授权额度调低到当前未清占用以下，需先清账或保持不低于当前占用 |
| D6 报表日期 | 已完成订货金额及订货量按完成日期统计；商品差价利润只统计履约完成订单，默认按首次发货日期筛选；结算仍按首次发货原周期，资金流水按发生时间并支持业务日期筛选 |
| D6 现结 | 按供应商执行订单逐单结算，不把同日多单自动合为日结；补发仍关联原执行订单及其原结算单 |

D1 技术栈、D7 部署及恢复目标按架构文档执行。资源规格、账号绑定、通知阈值及历史数据初始化清单在实施阶段补齐，不改变上述已确认业务边界。

## 2. 项目概述

### 2.1 项目背景

本系统是一套面向连锁餐饮企业自用的 **B2B 订货与供应商发货协同平台**，连接门店、总部采购、供应商和财务角色：

- **门店端**：在移动端发起采购下单、跟踪订单状态、查看数据报表
- **门店老板 / 财务**：查看本门店订单记录、报表、储值、挂账、未结算账单
- **总部采购**：确认门店订货单，必要时修改商品数量、增删商品或拒单，并将确认后的订货单拆分给供应商
- **供应商端**：接收采购确认后的订单，处理发货、配送方式、运费、缺货补发和订单统计
- **总部财务 / 平台管理端**：维护门店、供应商、商品、定价、模板、账期和财务结算规则，查看全量订单和报表

系统的核心价值在于：用门店订货模板串起"下单 → 采购确认 → 按供应商拆单 → 供应商发货 → 门店收货 → 缺货/退货处理 → 财务结算"全流程，并支持储值、挂账、供应商账期、公司账期等多种结算方式。商品供货价和门店销售价可以不一致，公司可在差价中获得利润。

### 2.2 系统范围

| 子系统 | 用户 | 形态 |
|---|---|---|
| 客户端 — 小程序端 | 门店、门店老板/财务、供应商、采购 | 移动端小程序 |
| 客户端 — 网页管理后台（全功能管理后台） | 平台管理员、采购、总部财务、供应商 | Web 应用 |

> 系统说明：一个程序内根据登录的账号权限展现不同功能。

首版由后台维护门店，不对接第三方门店数据，不做申请审批流；储值由后台充值，不接在线支付；保留单组单位换算，不做进货单、入库、出库和库存管理。

### 3.2 业务流程主轴

```
门店下单（余额不足也可提交） → 公司采购校验资金并确认（可拒单）
  → 按供应商拆分并推送 → 供应商发货 → 门店收货 / 供应商处理差异 → 履约完成
余额不足 → 采购提示并通知门店充值 → 重新校验通过 → 采购确认后才拆分推送
```

## 4. 功能需求 — 小程序端（门店端）

### 4.1 门店订货

#### 4.1.1 入口与前置条件

- 入口：小程序首页 → 门店端 → 门店订货
- 前置：门店账号已登录；门店状态为"启用"

#### 4.1.2 发起订货字段

| 字段 | 必填 | 业务规则 |
|---|---|---|
| 订货门店 | 是 | 当前登录门店；总部后台采购可代门店发起订货单 |
| 订货日期 | 是 | 默认当日；可选择其他日期 |
| 订货商品 | 是 | 只能选择该门店绑定的订货模板中的商品，价格取模板中配置的门店销售价 |

门店订货商品范围由后台"门店订货模板配置"控制；同一个门店只能命中一个有效订货模板，避免同一商品出现多套销售价或供应商分配规则。

#### 4.1.3 结算方式自动匹配

> 已确认：供应商设置默认结算方式，门店模板可以覆盖；模板覆盖值优先，未覆盖时使用供应商默认值。门店下单不手动选择。

门店下单时不需要手动选择结算方式。供应商维护默认值；门店订货模板可按供应商覆盖。匹配优先级为“当前门店模板中的供应商覆盖值 > 供应商默认值”，同一模板内同一供应商只有一个有效结算方式。订单保存匹配来源和配置快照；采购更换供应商时重新匹配并核算资金。

| 结算方式 | 适用方 | 关键规则 |
|---|---|---|
| 储值余额 | 门店预充值余额支付 | 可用储值充足时冻结应付金额，收货完成后实际扣款；不足可提交待补足订货单，采购无法确认、拆单或推送；充值后重新校验冻结 |
| 挂账 | 门店与公司挂账支付 | 未清挂账金额加本次新增占用不得超过授权额度；超额不可挂账下单，采购调整金额后仍需复核额度 |
| 供应商账期结算 | 门店与供应商直接结算 | 门店与供应商直接按供应商账期结算，一般供应商供货价与门店采购价一致，不涉及加价 |
| 公司账期结算 | 门店与公司账期结算 | 门店先按账期结算给公司，公司再结算给供应商；供应商供货价与门店采购价可存在差价，公司形成利润 |

> 注：订单生成后尚未实际付款时为 **已下单未支付**；储值冻结不算支付，收货后扣款足额才为 **已支付**。

余额不足的订货单保存为待采购确认、资金待补足，不透支冻结；充值只增加账户余额，不自动确认采购或推送。采购再次确认时按最新应付金额减已冻结/实际扣款校验并冻结差额。多供应商订货单在资金校验通过前不得拆分推送；并发订单以账户锁内可用储值为准，不能重复占用同一笔余额。挂账超额规则不变。

### 4.2 订单状态

| 状态 | 触发动作 | 说明 |
|---|---|---|
| 已下单状态的订单 | 门店下单后 | 待公司采购确认 |
| 待收货订单 | 公司采购确认 → 拆分给供应商 → 供应商发货 | 包含 **已发货**、**缺货补发** 两种子状态 |
| 已完成订单 | 门店确认收货 → 订单完成 | 全部商品收货完成 |
| 挂账未销账订单 | 订单完成但结算方式为挂账 | 订单列表 + 累计金额 |
| 未结算订单 | 账期或挂账订单尚未付款/清账 | 按时间或供应商筛选；账期支持批量付款登记，供应商直接账期由供应商确认收款，公司账期由总部财务确认；挂账进入总部财务清账流程，公司向供应商付款另行记录 |

> 注：以上为列表视图。履约、支付和两侧结算状态分别保存，见 §5.7；付款确认是线下付款登记，不代表系统发起银行转账。

| 挂账待销账金额 | 当前未结算挂账金额 | – |

## 5. 功能需求 — 业务流程（订单生命周期）

### 5.1 门店订货

门店发起订货单（总部后台采购可代门店发起订货单）。

- 步骤：选择订货门店 → 选择日期（默认当日）→ 选择订货的商品

### 5.2 订单拆分

采购确认且资金校验通过后，根据门店订货模板规则拆分，**同次订货以供应商为准，每个供应商对应一个执行订单**。采购确认前仅展示拟分配结果，不生成可供供应商处理的执行订单。

规则：

- 若订货商品只有一个供应商，默认分配给该供应商。
- 若订货商品有多个供应商，默认分配给排序第一或模板规则指定的供应商。
- 采购确认时支持按分类批量选择商品并调整供应商；目标供应商必须可供应每条被选商品，不符合时逐条提示。
- 每条商品只分配给一家供应商；同一种商品不拆数量分配给不同供应商，也不以重复商品行绕过该限制。
- 拆单后的子订单需保留原始订货单号、门店、商品、供应商、供货价、销售价和结算方式，便于财务追踪差价与账期。

### 5.3 公司采购确认

- 门店发起订货单后，门店订货单为未确认状态；采购确认管理里有"门店订货单"列表
- 采购可对订单进行确认或修改（可修改订单的商品数量或新增/删除商品）
- 采购列表和详情显示应付、已支付、储值冻结、门店可用余额和资金缺口；余额不足时允许保留订货单，但采购无法确认，不得拆分推送供应商。采购通知门店充值后，重新校验并确认。
- 修改数量、供应商或价格后，重新计算结算方式、金额及差额；资金校验、冻结调整、确认和拆单需保证一致性，失败时不能部分推送。
- 确认后订单将按供应商和商品的分配规则进行自动分配给供应商
- **可拒单**：拒单则订单取消
- 采购确认后才向供应商推送订单；供应商不可处理未确认订货单

### 5.4 供应商分配规则

对门店订货单里的商品按一定规则拆分给对应的供应商。

> **示例**：如有鸡和菌子 2 种商品，鸡有 A 和 B 供应商，下单的 A 门店关联 A 订货模板（该门店只下单鸡），则鸡分给 A 供应商。

### 5.5 供应商发货管理（可拒单）

收到推送的订单后，可移除或减少订单里的某个商品（**仅支持移除或减少，不支持增加**）。

| 字段 | 必填 | 业务规则 |
|---|---|---|
| 配送方式 | 是 | 自动带出供应商唯一配送方式，订单端不另选；记录本次发货配置 |
| 物流单号 | 否 | 配送方式为物流时可填写，本次发货/补发分别保存，订单详情可查询 |
| 运费 | 否 | 默认 0；按供应商是否需要运费设置录入；计入账单，门店承担和公司付供应商的运费相同 |
| 发货数量 | 是 | 实际发货数量 |
| 收货数量 | 是 | 门店端收货时填写；可修改、可减少收货数量 |

供应商确认发货后，向门店推送待收货消息，并记录实际发货时间、发货数量、当时的价格版本、运费和配送方式。账单按该供应商执行订单首次发货日期归入周期，后续补发仍归该周期。发货记录保留原值，但未完成订单仍适用历史生效改价重算，金额调整另留记录；履约完成后固定最终结算价格。

供应商拒单退回采购，采购可重新分配供应商或取消对应商品；其他供应商订单正常继续。取消部分释放储值冻结（历史已扣款则退款）或挂账占用，保留原分配及拒单记录。

补发默认不重复收运费，确需收取时由采购确认；这是订单费用确认，不引入通用审批流。加运费形成的资金差额按 §5.8 处理。

### 5.6 确认收货（门店端）

门店对订货的订单进行收货确认；点击确认收货后展开确认收货核对：

确认收货页面显示商品名称、发货数量、可编辑的实收数量（默认等于本次发货数量）及收货凭证。差异页展示订单号、日期、供应商和联系方式、各商品差异数量。

收货数量差异处理：

- 若收货数量未调整，门店上传收货凭证后可直接确认收货，订单完成。
- 若收货数量少于发货数量，订单进入"订单缺货/数量差异处理"页面，并向供应商推送缺货消息。
- 供应商选择"补发"：沿用原订单，不生成补发子订单；按供应商配送方式记录补发，推送门店再次收货。每次发货、收货保留独立记录，最终实收数量为首次有效实收加各次补发有效实收，禁止覆盖或重复累计。
- 补发沿用原单价格及原订单首次发货日期所属账期，跨半月、月或年均不改变归属；补发日期仅用于履约记录，不生成新的订货/执行订单，也不重复计算原订单货款。
- 供应商选择"退回确认"：订单退回门店，由门店重新核对并确认收货；原差异记录保留，重新确认不重复计入实收数量。
- 供应商选择"同意"：按门店填写的实际收货数量完成履约并调整应收应付；自动退回储值差额或释放挂账占用，付款/核销状态另行处理。

### 5.7 订单状态机

履约状态与资金状态分别保存：

| 维度 | 状态 / 规则 |
|---|---|
| 履约 | 待采购确认 → 待发货 → 待收货 → 已完成；异常可进入差异处理中、待采购重新分配或已取消 |
| 门店资金 | 未支付、待补足、已支付；挂账未清；账期未付款、已付款待收款方确认、已结清；退款记录单独保留 |
| 公司对供应商结算 | 未付款、已付款待供应商确认、已结清；不与门店付款状态共用一个字段 |
| 原始订货单汇总 | 根据全部执行订单归纳，不能因一家供应商完成就标记整单完成 |

余额不足的订单保持待采购确认并显示待补足；已支付并不表示已完成。补发沿用原订单，所有有效收货和差异处理结束后才完成履约。

### 5.8 订单金额调整

- 减量、取消和少收同意：未扣款部分释放冻结，已实际扣款部分退回差额，或释放对应未清挂账占用；不产生重复退款，不改变历史已发生流水。
- 增量、供货方变更、历史涨价、新增运费：按最新金额减已有有效冻结/扣款计算差额，重新校验并调整冻结（已收货或历史已扣订单调整实际扣款）或增加挂账占用；结算方式变化需冲回原资金占用后按新方式记账，保留关联记录。
- 待采购确认时余额不足：订货单保留，采购提示缺口并通知充值；充值后采购重新校验确认，才拆分推送。
- 已确认但未发货时出现待补差额：暂停后续发货，通知采购及门店补足；已发货订单允许正常收货，差额未处理前不标记资金结清。
- 挂账调整不得超授权额度，超额显示待处理并阻止对应确认/后续发货；原超额挂账下单拦截规则保持不变。
- 应收、应付和利润采用相同的有效数量与价格版本。已出账但未结清时更新账单金额，保留调整前后金额、原因、操作人、时间及来源；已付记录不被覆盖，只调整剩余应收应付。
- 已结清账单保留原值，另生成关联原订单、原账单及原归属周期的差额调整单，在后续结算中补收/补付或抵扣；调整单只记差额，不新增补发订单或重复记整单货款。
- 门店与供应商两侧按各自账单是否结清处理调整；供应商总单及分店单共用调整明细，不重复计账。此规则不允许对已完成订单追溯改价，价格重算仍限于 §6.1.1 的适用订单。

## 6. 功能需求 — 网页管理后台（全功能管理后台）

### 6.1 商城管理

#### 6.1.1 商品字段

| 字段 | 必填 | 业务规则 |
|---|---|---|
| 商品名称 | 是 | – |
| 条码 | 否 | – |
| 货号 | 否 | – |
| 商品分类 | 是 | – |
| 销售单位 | 是 | – |
| 销售价格 | 是 | 默认销售价 |
| 供应商供货价 | 否 | 按商品与供应商关联维护，填写销售单位对应的采购价；不同供应商价格可不同，首版不涉及仓库库存 |
| 品牌 | 否 | 下拉选择产品品牌 |
| 关联供应商 | 否 | 下拉选择已有的供应商，支持多选（同一个商品可能有多个供应商） |
| 采购单位 | 否 | 默认不启用；启用后仅维护一组销售单位与采购单位换算关系，例如一包 = X 袋，用于订单数量和价格单位换算；首版无入库、出库和库存功能 |
| 起订量 | 否 | 门店订货时该商品的最低起订数量；如设置 5 则最低起订 5 件；默认 1；商品及模板覆盖值必须为正整数，不允许小数 |
| 订货倍数 | 否 | 门店订货时该商品必须按整数倍订购；如设置 3，则仅支持 3/6/9 等数量；默认 1；商品及模板覆盖值必须为正整数，不允许小数 |
| 储存条件 | 否 | 常温 / 冷藏 / 冷冻 / 保温 |
| 产品图片 | 否 | 1:1 比例，非正方形图片在上传预览时支持裁切；大于 2M 自动压缩 |

价格规则：

- 商品可维护销售价和采购价，供货价与销售价允许不一致。
- 仓库采购价在商品新增/编辑表单内按关联供应商选填，按销售单位报价，允许不同供应商不同价格。商品、关联和采购价一次提交、同一事务保存；留空不调整已有采购价，未变更价格不新增版本。系统记录当前生效时间和维护原因，不要求填写时间/原因或另做影响预览。沿用共享价格版本和既有结算规则；独立价格管理界面已撤下，底层历史价格记录与重算逻辑暂保留，来源待核实，不新增库存模块。
- 采购和管理员可在授权端维护价格；采购支持小程序、网页双端快速改价。门店销售价取当前有效模板中的商品/供应商价格；默认商品价只用于初始化配置，不覆盖已维护的模板价。供货价按所分配供应商的有效价格版本取得。
- 商品价格变更需支持生效时间；允许立即生效、指定未来时间生效、指定过去时间生效。
- 已完成订单使用订单完成时的价格快照，后续改价不追溯影响已完成订单。
- 未发货且未完成订单：历史生效时间之后创建的订单按有效新价重算；发货时再核对当时有效价格。未来价格不得在生效前应用。
- 已发货但未完成订单：按最新补充图，以发货时间判断价格适用性；改价生效时间早于发货时间时同步更新销售价，供货价按其有效版本核算。例如 14 日下单、16 日发货、17 日将价格设为 15 日生效，该未完成订单需重算，不能因下单早于生效时间而排除。
- 保存原价、新价、生效时间、影响订单及资金调整记录；发货时间点起有效的新价格适用于该时点的发货。已完成订单不追溯改价的既有规则保持不变。
- 补发商品按原单价格，不按补发当天价格重新取价；未完成订单的历史生效改价仍以原订单首次发货时间判断，适用时更新原单及其补发的价格口径并保留调整记录。
- 用户选择的订货日期不替代系统创建或首次发货时间；补发实际日期仅记录履约，不改变价格和账期基准。

#### 6.1.2 商品分类

- 分类级数：二级分类，支持自定义新增、修改分类
- 删除规则：该分类下无商品可删除；删除后该分类历史已有数据不变
- 修改规则：修改后历史也会同时响应变更

#### 6.1.3 商品品牌

- 品牌名称与商品品牌字段关联，支持自定义添加、修改和删除
- 删除规则：该品牌下无商品可删除；删除后该品牌历史已有数据不变
- 修改规则：品牌名称修改后历史展示同步更新，不改变历史交易金额

#### 6.1.4 商品单位

- 单位名称 → 支持自定义添加和修改删除
- 删除规则：该单位下无商品可删除；删除后该单位历史已有数据不变
- 修改规则：单位名称修改后展示同步更新；历史交易单位及换算数值保留快照，不因改名或改换算关系而重算已完成订单

#### 6.1.5 商品管理员规则备注

### 6.2 配送方式 / 结算方式管理

#### 6.2.1 配送方式配置

- 配送方式按供应商配置，一个供应商只有一个配送方式，自配送、物流二选一。
- 发货及补发自动带出并展示供应商配送方式，不在订单端另选；不按商品、门店、订货模板分别配置。
- 配送方式为物流时，发货可填写物流单号；由供应商录入本次发货信息，但不能因此修改基础配送配置。
- 配送方式与运费一起进入订单账单，运费可为 0。

#### 6.2.2 结算方式管理

供应商基础资料维护默认结算方式；模板内的结算方式管理仅展示该模板商品已关联的供应商，可逐个设置覆盖值或使用默认值。优先使用模板覆盖值，未覆盖则使用供应商默认值。门店下单自动匹配；后续配置修改不直接改写现有订单的结算快照，采购换供应商时按 §5.8 重新核算。

| 结算方式 | 业务含义 | 状态联动 |
|---|---|---|
| 储值余额 | 门店用预充值余额支付 | 可用余额充足则冻结，收货完成扣款；不足可提交待补足单，采购确认、拆单及推送被拦截 |
| 挂账 | 门店在授权额度内先下单后清账 | 超过挂账额度不可下单，订单支付状态为已下单未支付 |
| 供应商账期结算 | 门店与供应商直接按账期结算 | 订单支付状态为已下单未支付 |
| 公司账期结算 | 门店先与公司结算，公司再与供应商结算 | 订单支付状态为已下单未支付 |

#### 6.2.3 结算方式与订单状态联动

| 结算方式 | 自动匹配后订单支付状态 |
|---|---|
| 储值余额 | 冻结后仍未支付，收货扣款足额才已支付；可用余额不足为待补足，不拦截提交、拦截采购确认 |
| 挂账 | 已下单未支付 |
| 供应商账期结算 | 已下单未支付 |
| 公司账期结算 | 已下单未支付 |

#### 6.2.4 模板操作

| 操作 | 规则 |
|---|---|
| 复制 | 复制除适用门店外的全部配置，保留商品、供应商、价格及结算覆盖值，名称追加“副本”；仍须满足名称唯一 |
| 删除 | 删除该模板，删除了该模板所有关联关系取消 |
| 新增 | 模板名称、模板标签均为文本自定义、必填 |

| 累计挂账金额 | 历史挂账发生额汇总，与当前未清金额分开；清账不减少累计发生额，冲销记录单独可查 |
| 挂账未清金额 | 有效挂账应付扣除已清金额及取消/减量释放的金额 |

##### 6.4.3.3 清账流程

挂账为门店尚未向公司支付的货款，先记欠款。下单占用额度，不扣储值、不记已付款；按约定周期收到还款后，由财务批量销账（系统称清账）。到期本身不自动清零；销账恢复可用额度，不减少授权额度或历史累计挂账发生额。

1. 总部财务或平台管理员点击"清账"
2. 展开该门店未清挂账订单，支持按日期、供应商筛选
3. 按约定结算周期筛选并批量选择订单，核实已收到门店还款，展示本次金额、上传图片凭证 → "确认清账"（按钮与单据统一称清账）
4. 所选订单资金状态变为"已结清"，未清金额减少、剩余额度增加；不修改履约状态，不将其他未清订单一起清零
5. 系统生成财务流水，记录订单类型、金额、操作人、时间
6. 系统生成独立清账单，记录本次清账关联的门店和订单、金额、日期及操作时间、操作人、备注及图片凭证；凭证可在清账单和关联流水查看

##### 6.4.3.4 充值流程

1. 总部财务或平台管理员进入财务管理，点击"充值"，选择对应门店
2. 录入充值日期、充值金额、收款账户、备注，上传图片凭证；系统记录所选门店、操作人及录入时间，凭证与充值记录关联
3. 提交后生成充值记录，门店储值余额增加
4. 储值订单下单或补足后冻结资金，收货完成才扣款并记录资金流水；充值本身不自动拆单推送，也不自动扣款

## 8. 端到端业务流程

### 8.1 主流程（Happy Path）

```
门店下单
  ↓
公司采购确认（人工确认，可拒单）
  - 可修改数量、增加/删除商品
  - 余额不足显示缺口，通知充值，禁止确认/拆分/推送
  - 充值后重新校验并扣足差额
  - 确认后才推送供应商
  ↓
系统按订货模板 + 供应商规则拆分订单
  ↓
供应商发货管理
  - 移除/减少商品（仅减）
  - 展示供应商配送方式
  - 填入运费
  ↓
门店确认收货（核对数量、修改收货数量）
  ↓
订单完成
  ↓
（若结算方式为挂账 / 账期）→ 进入未结算订单 → 财务结算
```

### 8.2 异常流程

| 异常 | 处理 |
|---|---|
| 公司采购拒单 | 订单状态变为"已取消"；通知门店 |
| 供应商无可发库存 | 缺货补发；订单进入"待收货（缺货补发）"子状态 |
| 收货数量与发货数量不一致 | 门店提交差异，供应商处理补发 / 退回确认 / 同意 |
| 供应商选择补发 | 原订单增加补发记录，再推送门店收货，累计有效实收数量 |
| 供应商选择退回确认 | 订单退回门店，由门店重新核对并确认收货 |
| 供应商选择同意 | 按实际收货数量完成履约并调整资金及账单 |
| 供应商拒单 | 退回采购重新分配或取消对应商品；不影响其他供应商订单，取消部分退回资金或释放额度 |
| 供应商已发货但门店未确认 | 订单停留在"待收货"；超时自动催收 |
| 挂账金额超额度 | 下单拦截；提示门店充值或联系后台调整结算方式 |
| 储值余额不足 | 允许下单，采购可见资金缺口但无法确认、拆分或推送；采购通知门店充值后重新确认 |

### 8.3 财务流程

```
门店下单 → 模板供应商覆盖值优先，否则使用供应商默认结算方式
  ├─ 储值充足 → 冻结 → 采购确认推送 → 收货完成后扣款
  ├─ 储值不足 → 订货单保存 → 采购提示缺口并通知充值
  │              → 充值 → 采购重新校验并冻结 → 拆分推送 → 收货完成扣款
  ├─ 挂账 → 校验并占用额度 → 按选中订单清账 → 生成流水和独立清账单
  ├─ 供应商账期 → 门店登记付款 → 供应商确认收款
  └─ 公司账期 → 门店销售价账单 → 门店付款 → 总部财务确认收款

公司账期 / 储值 / 挂账 → 公司对供应商供货价应付账单
  → 公司登记付款 → 供应商确认收款
```

公司账期按供应商配置的结算周期汇总，门店先结算给公司，公司再结算给供应商。储值和挂账同样生成公司对供应商的周期应付，门店付款方式不影响公司供货价应付的计算。

供应商直接账期由门店与供应商结算，通常供货价与门店采购价相同，不生成公司同额应收应付。直接账期记录与公司对供应商结算记录分开查询，避免混入公司应付。

#### 8.3.1 账单与汇总单

| 单据 | 汇总维度 | 金额口径与用途 |
|---|---|---|
| 门店账单 | 门店 + 供应商 + 周期 | 公司销售价计算门店应付，运费单列；公司账期由门店登记付款、总部财务确认 |
| 供应商周期汇总单 | 供应商 + 周期 | 供货价汇总公司对该供应商的应付，查询双方整体结算情况 |
| 供应商门店周期汇总单 | 供应商 + 周期 + 门店 | 供货价汇总该供应商在各门店的供货及结算情况，可独立查询并关联周期总单 |

两种供应商汇总单均需提供查询入口和汇总单展示，关联同一组应付明细及核销记录，不新增第二笔应付；分店单金额之和等于周期总单金额，已付/未付同步汇总，禁止从两个入口重复核销。门店账单与供应商分店单虽然维度相同，但分别用销售价、供货价，不能混用。

单据至少展示单号、周期、供应商、门店（适用时）、来源订单和发货记录、数量、单价、商品金额、运费、调整额、已付、未付及确认状态。付款登记记录金额、时间、操作人和凭证；按来源明细关联，重复操作不能重复生成账单或资金流水。

储值/挂账的门店侧展示相应扣款或清账记录，不再当作公司账期重复要求门店支付；供应商侧仍按供货价出应付。

#### 8.3.2 周期归属

- 按供应商执行订单首次实际发货日期归入结算周期，不按下单或收货完成日期。例：15 日首次发货、16 日收货归上半月；15 日下单、16 日首次发货归下半月。
- 原单补发不新增订单，全部沿用原订单首次发货日期账期。例：15 日首次发货、17 日补发，两次均归上半月；门店账单、供应商周期总单及分店汇总单使用相同归属。
- 周结为自然周，周一至周日；半月结为每月 1-15 日、16 日至月底；月结为自然月。使用业务时区 Asia/Shanghai，每个日期只属于一个周期。
- 未发货订单不因已下单或已扣款而计入发货周期账单；已发货未收货可按发货数量展示待核对金额，收货差异确认后调整为有效实收，不将归属改成收货周期。
- 现结不累计周/月周期。跨期补发及调整保留原订单首次发货周期；原账单未结清则更新并留痕，已结清则以关联调整单纳入后续结算，原账单和原交易周期不被改写。区分“原交易归属周期”与“调整单实际结算周期”，不能把补发重新算作下一周期的新采购。

#### 8.3.3 运费与利润

- 同一订单门店承担运费与公司支付供应商运费相同；商品金额和运费分开显示。补发默认不重复收运费，额外运费经采购确认。
- 商品差价利润 = Σ（最终实收数量 ×（有效销售单价 − 有效供货单价）），按相同计量单位计算；运费单列，不纳入商品差价利润，不称为公司净利润。
- 利润报表支持订单、商品、门店、供应商和时间筛选，仅采购、总部财务和管理员可见。

## 9. 非功能需求

### 9.1 性能

| 项 | 指标 |
|---|---|
| 小程序首屏加载 | ≤ 2s（4G） |
| 订单列表查询响应 | ≤ 1s（单页 20 条） |
| 数据报表加载 | ≤ 3s |
| 并发下单 | ≥ 200 QPS |
| 报表导出（Excel） | ≤ 10s（10 万行内） |

### 9.2 数据一致性

- 订单状态变更需保证最终一致性；不允许出现"已发货但订单仍为已下单"等不一致状态
- 挂账金额、储值余额及冻结变更需事务化；下单冻结、采购补冻结、收货扣款、冲销退款保证原子性和幂等性。余额不足允许保存待确认单，不能透支或部分推送
- 多供应商拆分订单需保证拆分明细可追溯
- 订单确认/发货保存价格及配置版本；未完成订单按生效规则调整价格并保留变更记录，已完成订单最终价格不受后续改价影响
- 单位换算保持精度一致，订货、发货、收货和利润计算不得单位错配；首版不含库存或入库
- 两种供应商汇总单共用应付明细和核销记录，总额与各门店汇总一致，不重复计账

### 9.3 异常处理

| 场景 | 处理 |
|---|---|
| 网络异常 | 小程序端提示重试；订单本地缓存待恢复后提交 |
| 冻结/扣款结果不确定 | 按操作标识查询并核对冻结或资金流水，幂等重试；未核对冻结结果不重复推送，未核对收货扣款结果不重复扣款 |
| 并发抢单 | 乐观锁；冲突方提示"订单已被处理" |
| 供应商不可达 | 订单保留在"已拆分"状态；超时通知平台管理员 |

### 9.4 安全

- 账号密码复杂度要求
- 关键操作（清账、拒单、修改模板）需记录操作日志
- 财务数据按 §7 的角色、归属和字段权限展示，接口与导出执行相同限制

## 10. 验收标准

### 10.1 主流程验收用例

| 编号 | 场景 | 期望结果 |
|---|---|---|
| AC-01 | 门店 A 下单 5 种商品，3 种分配 X、2 种分配 Y | 采购确认及资金校验前不推送；通过后拆为 X、Y 两单，每条商品只分一家 |
| AC-02 | 采购账号代门店 A 下单 | 订货门店显示为 A；订单状态正常 |
| AC-03 | 供应商 X 发货时将 3 件减为 2 件 | 订单显示发货数量 2；门店收货数量最大为 2 |
| AC-04 | 门店 A 下单，系统自动匹配为"储值余额"，且可用余额充足 | 余额不减、冻结增加、可用余额减少；收货完成后余额扣减、冻结释放，实际支付足额为已支付 |
| AC-05 | 门店 A 下单，系统自动匹配为"挂账"，且未超挂账额度 | 订单支付状态为"已下单未支付"；累计挂账金额增加 |
| AC-06 | 自动匹配挂账，未清金额加本次金额超过授权额度 | 下单拦截，提示联系财务清账或调整额度；门店不自行选择结算方式 |
| AC-07 | 供应商发货后，门店确认收货 | 订单状态变为"已完成" |
| AC-08 | 订单完成后查看订货金额报表 | 累计增加该订单有效金额，而不是订单笔数；不同结算方式均统计 |
| AC-09 | 商品价格设置为次日 0 点生效，门店今天下单 | 今天订单使用旧价；次日 0 点后新订单使用新价 |
| AC-10 | 同商品多个供应商，模板默认 Y，采购按分类批选改分配 X | 逐条校验 X 可供货，确认前仅调整分配；不将同商品数量拆给多家，确认后按最终供应商拆单 |
| AC-11 | 门店选择供应商账期订单并批量付款确认 | 订单状态变为已付款待供应商确认；供应商确认后变为已结算完成 |
| AC-12 | 平台为门店充值 1000 元 | 生成充值流水；门店储值余额增加 1000 元 |
| AC-13 | 14 日下单、16 日发货且未完成，17 日改价设为 15 日生效 | 按发货时间适用新价，记录差额；已完成订单不变 |
| AC-14 | 公司授权角色查看利润报表 | 最终实收数量乘销售与供货单价差，运费单列；支持门店/供应商/商品/时间筛选，门店和供应商不可见 |
| AC-15 | 平台管理员新增或编辑门店资料 | 后台门店列表更新对应门店资料，门店状态和财务配置可正常生效 |
| AC-16 | 储值订单 500 元，余额 100 元 | 允许提交待采购确认单，显示缺口；无法采购确认、拆单、推送，不透支余额 |
| AC-17 | AC-16 门店充值 400 元，采购再次确认 | 充值不自动推送；采购重新校验，冻结 500 元后拆分推送；收货完成后只扣 500 元，重复提交不重复冻结或扣款 |
| AC-18 | 同供应商默认公司账期，模板 A 覆盖储值、模板 B 未覆盖 | A 门店自动匹配储值，B 门店自动匹配公司账期；模板 A 清除覆盖后，新订单使用供应商默认值，既有订单结算快照不被改写 |
| AC-19 | 15 日发货、16 日收货；另一单 15 日下单、16 日发货 | 前者归上半月，后者归下半月，不按下单或收货日期归账 |
| AC-20 | 公司账期同供应商向两家门店供货 | 每店有销售价账单；供应商有供货价周期总单和两张分店汇总单，总单等于分店之和，核销不重复 |
| AC-21 | 门店分别使用储值、挂账采购 | 门店侧扣款/挂账，公司对供应商仍按供货价和发货周期生成应付，不重复收取门店货款 |
| AC-22 | 商品实收 10 件，销售价 12 元、供货价 9 元，运费 5 元 | 公司账期门店应付 125 元、公司供应商应付 95 元；商品差价利润 30 元，运费单列 |
| AC-23 | 物流配送发货并录入物流单号 | 原发货及补发各自保存单号，门店/供应商对应订单可见，供应商不能修改基础配送配置 |
| AC-24 | 总部财务充值或清账 | 选择门店、上传图片凭证，保存金额、日期、操作人和凭证；清账同时生成独立清账单 |
| AC-25 | 供应商尝试改商品、价格、供应商资料或结算方式 | 网页及小程序无编辑权限，接口拒绝；自己的商品可查看、自己的订单可处理 |
| AC-26 | 15 日首次发货、17 日补发，同月 16 日商品发生普通调价 | 不新增订单，补发沿用原单价格，两次均归上半月；三种汇总单无重复货款 |
| AC-27 | 15 日首次发货的未完成订单，18 日将价格设为 14 日生效，17 日已有补发 | 以首次发货时间判断历史改价，原单和补发按同一有效新价核算并记录差额；已完成订单不重算 |

### 10.2 异常流程验收用例

| 编号 | 场景 | 期望结果 |
|---|---|---|
| AC-E01 | 采购拒绝已扣储值或占挂账额度的订货单 | 取消并通知门店；已扣金额退回或额度释放，重复操作不重复退款 |
| AC-E02 | 供应商 X 缺货 1 件，发货 2 件 | 订单进入"缺货补发"子状态；剩余 1 件后续补发 |
| AC-E03 | 门店收货数量有差异 | 门店提交差异，推送供应商处理；门店不可代供应商选择同意/退回确认 |
| AC-E04 | 门店挂账金额超过挂账额度 | 下单失败 |
| AC-E05 | 未清挂账 1000 元，财务选取 300 元订单确认清账 | 未清变为 700 元，剩余额度增加 300 元，历史累计不减少；生成流水和带图片凭证的清账单 |
| AC-E06 | 供应商发货后门店长时间未确认 | 系统自动催收通知 |
| AC-E07 | 首次发货 10 件、实收 8 件，供应商选择补发 2 件并收到 | 沿用原订单保留两次收货记录，最终实收 10 件；补发不重复计货款或默认运费 |
| AC-E08 | 门店少收，供应商同意按实际数量结算 | 调减应收应付、退回对应储值或释放挂账额度，最终利润按实收计算 |
| AC-E09 | 供应商选择退回确认 | 回到门店重新核对收货，不重复累计实收数量 |
| AC-E10 | 供应商拒单，采购改分配或取消 | 退回采购处理，其他供应商订单继续；取消部分释放资金，改分配重新匹配结算及核算金额 |
| AC-E11 | 采购增量后或未完成订单历史涨价后余额不足 | 按 §5.8 显示差额；待确认单禁止确认及拆推，已发货单可收货但差额未处理不能资金结清 |
| AC-E12 | 账单未结清，少收或适用的历史改价使金额变化 | 更新原账单，保留前后金额及来源记录，已付款不被覆盖；供应商两种汇总同步且不重复计账 |
| AC-E13 | 原周期账单已结清，后续确认差异产生应收应付调整 | 原账单不变，生成关联差额调整单，在后续结算补收/补付或抵扣；原订单周期不变，不新增补发订单，重复处理不重复调整 |
