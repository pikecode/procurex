4. 下一步范围缺少优先级约束。最近拟优先开发完整服务端历史浏览、跨设备恢复和冻结商品快照重建；其中必要审计、原始单据可追溯和可靠命令恢复必须保留，但独立综合历史中心、额外浏览功能和无法从原始证据可靠重建的数据，不应先于原需求缺口。是否属于首版逐项按基线判定，不能默默扩大或删减范围。

## 固定收口顺序

三个交付包是组织剩余工作的边界，不是三个微小修改，也不表示原计划只剩三个功能。

1. **正式业务入口包**：先逐项盘点基础资料已有接口和页面，补齐原需求缺口；完成正式 Web 的登录、角色范围、商品/门店/供应商/模板/价格维护及业务处理，消除正常工作流中手填 UUID、接口版本和查看原始返回的依赖。交付一套从配置到订货履约的可操作本地验收流程。不得仅因页面使用 HTML 就重写框架。
2. **财务关闭包**：集中处理剩余挂账清账后调整、来源对账和结算模式汇总；覆盖先收后付、总分单共享核销、已结清差额及重复请求，完成计划标准金额回归。涉及财务阻断的缺陷可提前处理。以现行证据关闭 M4，不沿用旧截图；刷新受影响 M5 证据。
3. **发布验收包**：统一正式入口及操作路径，完成原需求逐条结果清单、角色联调、兼容性、必要故障恢复和干净环境复现；准备发布候选版本及交接。真机和生产外部条件单列，条件未具备时只宣布本地候选版本完成，不宣布上线完成。

必要审计、权限、幂等、故障恢复和账款可追溯不可作为“细节”删除。新增综合历史中心、跨设备体验扩展、无可靠依据的历史回填，不默认进入上述工作包；发现属于基线要求时明确映射后纳入。
